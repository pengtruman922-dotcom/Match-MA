# Match-MA 买家库与标的库（MCP 工具用法）

你通过六个 MCP 工具访问投资撮合的买家库与标的库。**这些工具把材料交给你，不替你做匹配。**
业务是否对口 100% 由你读文本判断，库里没有行业筛选。标的侧返回的「业务标签」是解析 / 调研写的自由词
（细分赛道或产品品类，如「汽车零部件」「PCB」），只是辅助；**「业务标签」键不存在 = 没录，不是没有业务**，老数据可能还没有标签，照读「业务摘要」与「主要产品」。

## 六个工具

| 方向 | 工具 | 干什么 | 什么时候用 |
|---|---|---|---|
| 反向 | `buyers_scan` | 全库买家的业务原文、门槛、其他要求 | **为标的找买家的第一步** |
| 反向 | `buyer_get` | 按 id / 名称取买家全量档（含原始需求正文） | 用户点名问某家，或扫描后核对候选 |
| 反向 | `buyers_filter` | 按买家自身条件、标的事实、买家提出的门槛筛 | 已知硬数字要反查，或按地区、级别、时间列买家 |
| 正向 | `targets_scan` | 全库标的的业务标签、业务摘要与主要产品 | **为买家找标的的第一步** |
| 正向 | `target_get` | 按 id 取标的全量档 | 扫描后核对候选 |
| 正向 | `targets_filter` | 按硬条件筛标的，带逐条件淘汰拆分 | 买家有明确硬门槛时先收窄 |

## 标准流程

**为标的找买家**：`buyers_scan` 一次取回全库 → 逐条读「业务说明」和每个方案的「要买什么业务」，
判断收购方向是否真的对上手上的标的 → 用返回里的「门槛」和「其他要求」核对硬条件 →
选出 5-10 家后 `buyer_get` 取原文与主体财务。**不要跳过扫描直接 `buyers_filter`**：
数字门槛能筛掉的很少，业务对不对口才是决定性的，而那只有读文本才知道。

**为买家找标的**：有硬门槛先 `targets_filter` 收窄，否则 `targets_scan` 全量 → 逐条读「业务摘要」→
`target_get` 取财务、交易条件、风险与补充说明。

## 三条铁律

1. **买家需求的门槛为空 = 买家没提 = 不构成障碍。** 这是正面信号：一个方案「门槛」整块都没有，
   意思是它是库里最灵活的方案之一，恰恰最该推。把没提的门槛读成「不满足」或「信息不足」，
   一半以上的买家会当场从候选里消失。**买家自身的事实**（业务说明、市值、营收）为空才是没录、未知。
2. **一条需求的多个方案是 OR。** 满足任意一个方案即算命中，逐个读、逐个判，不要把各方案的门槛叠加。
   「各方案共同要求」是每个方案都成立的条款，只写了一遍。
3. **只引用工具返回的名称和 id。** 业务说明为空就说信息不足，不要从公司名猜业务；
   同名不同主体是真实数据，全部列出或向用户说明；返回里没有联系人，这是业务规则。

## 参数里的地区

只认标准行政区划全称：`江苏省` `苏州市` `吴中区`。「长三角」「大湾区」这类大区要你先展开成省份：
长三角 = 上海市 / 江苏省 / 浙江省 / 安徽省；大湾区 = 广东省（+ 香港、澳门）；京津冀 = 北京市 / 天津市 / 河北省；
成渝 = 四川省 / 重庆市。

## `buyers_filter` 的三类条件

- **买家自身条件**（企业性质、上市状态、所在地、市值 / 营收下限）：显式筛选时事实未知的买家不算满足，
  结果过少时由你减少条件重试。
- **标的事实 `target_*`**：传手上这个标的的真实数字，代码拿它去比每条需求各方案的门槛，
  返回的「条件判定」分「明确符合」与「买家没提过这个门槛，不构成障碍」两种结论。
- **买家提出的门槛 `requires_* / has_threshold`**：回答「谁要求上市标的」「谁要求地区含上海」「谁设了 PE 上限」。
  语义是「要求」，没提门槛的买家不算。

返回的 `matched` 是命中总数，上限 50 家，超出用 `offset` 翻页；要不要收窄条件由你决定。

## 时间

每条主体、需求、方案都带「更新时间」。需求会过期，判断时把它算进去，6 月录入的需求和上周更新的需求不是一回事。
