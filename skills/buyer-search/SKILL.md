# 买家检索（Match-MA 买家库）

手上有一个要出售的标的，在买家库里找谁可能想买它。

**这是一个把材料交给你的工具，不是一个匹配工具。** 业务是否对口 100% 由你读文本判断，
库里**没有行业筛选**这回事。

## Wegent 调用入口

本 skill 对外注册为一个 `search_buyers` 工具，使用 `operation` 选择查询形状：

- `business`：全库业务原文，通常第一步调用；
- `get`：按 `name` 或 `buyer_party_id` 取全量档案；
- `filter`：按买家自身条件和标的事实反查需求门槛。

只接受标准省、市、区名称。`长三角`、`华东` 等大区要由调用方 Agent 先展开，
再把标准行政区划传给 `filter`，skill 不把大区当作可筛值。

例如只看买家所在地在杭州的在库需求：

```json
{"operation": "filter", "city": "杭州市"}
```

Wegent 侧应注册目录中的 `tool.json` 并执行 `search_buyers.py` 的同名入口；
这个 skill 通过 HTTPS 调 Match-MA REST API，不依赖 Match-MA MCP server。

## 什么时候用

- 手上有一个标的（或一段出售需求描述），要找可能的买家。
- 用户问「谁在找 XX 这类公司」「这个项目推给谁」。
- 用户点名问某一家买家在找什么。

## 三个接口，是三种返回形状

| 接口 | 选谁 | 返回什么 | 什么时候用 |
|---|---|---|---|
| `search_buyers_business` | 全库 | 只有业务字段（薄） | **绝大多数情况下的第一步** |
| `get_buyer` | 按名称/id | 全量（厚） | 用户点名问某家买家 |
| `filter_buyers` | 条件组合 | 全量（厚） | 已知标的的硬数字，想按门槛反查 |

### 标准流程：先全量读，再取详情

1. **`search_buyers_business`** 一次取回全库买家的业务原文（约 200 家）。
2. **你逐条读「业务说明」和「要买什么业务」**，判断这家买家的收购方向是否真的对上了
   手上这个标的。这一步没有任何 SQL 参与，全靠你读。
3. 选出 5-10 家之后，用 `get_buyer` 取全量档案，核对财务门槛、地区、控股要求。

**不要跳过第一步直接用 `filter_buyers`。** 数字门槛能筛掉的东西很少
（大多数买家根本没设门槛），而业务方向对不对口才是决定性的 —— 那只有读文本才知道。

## ⚠️ 最重要的一条：两类「字段不存在」含义相反

返回里**值为空的字段会被整个省略**。看到一个字段不在，先分清它属于哪一类：

### 「买家信息」块里字段缺失 = 没录，未知

业务说明、市值、营收、企业性质这些是**买家自身的事实**。缺了就是没人录过，
**不能当成「这家公司没有」**。业务说明为空时如实说「信息不足，无法判断」，
**不要从公司名字猜业务**。

但如果你在 `filter_buyers` 里**明确传了买家自身条件**（企业性质、上市状态、
所在地、市值或营收），未知/空值不算满足，会被排除。结果过少时，由你判断是否
减少筛选条件后重试；不要在工具里把未知记录伪装成符合。

### 「收购需求 → 门槛」里字段缺失 = 买家没提这个门槛 = ✅ 不构成障碍

最低营收、可接受地区、可接受上市状态、要求控股这些是**买家提出的门槛**。
缺了表示**买家根本没提这条**，那是**正面信号**：这家买家在这一维上没有限制。

> 一条需求的「门槛」整块都空，意思是**这是库里最灵活的买家之一**，
> 恰恰最该推 —— 不是「信息不足所以跳过」。
>
> 把需求没提的门槛读成「不满足」，一半以上的买家会当场从你的候选里消失。
> 这是本工具最容易用错的地方。注意这条只针对**需求门槛**；买家自身事实若被
> 明确拿来筛选，未知就是不符合。

`filter_buyers` 的每条结果都带「条件判定」，把这两件事明确分开写出来了：

```
"条件判定": {
  "最低营收": "明确符合",
  "可接受地区": "买家没提过这个门槛，不构成障碍"
}
```

## 硬规则

1. **业务匹配只能靠读文本。** 买家说的是「薄膜电容器」「线控底盘」「固态电池」
   这类细分方向，任何行业字典都接不住 —— 所以库里干脆没有行业筛选。
   接口一没有关键词参数，这是设计不是遗漏。
2. **业务说明为空就说判不了。** 不要从公司名字猜它做什么。
3. **同名不同主体是真实数据。** 生产库里「北大健康」有 3 个主体、4 条需求。
   工具会把全部候选返回给你，**不要合并、不要只用第一个** ——
   如实按多条处理，或向用户说明有几条同名记录。
4. **一家买家可以有多条需求。** 它们是不同的收购方向，分别判断，
   不要把一家买家的多条需求当成同一件事。
5. **不要编造买家。** 只能引用工具返回的名称和 id，不要补充工具没给的数字或事实。
6. **`filter_buyers` 的 `target_*` 是标的的事实，不是你想要的门槛。**
   传标的自己的营收/净利/PE/地区，代码拿它去比每条需求各自的门槛。
7. **返回里没有联系人和联系方式，这是业务规则。** 不要向用户承诺能拿到，
   也不要去别处找。要联系人请用户在系统里查。

## 接口一 `search_buyers_business`

| 参数 | 类型 | 说明 |
|---|---|---|
| `detail` | 字符串 | `full`（默认，约 600 字/买家）或 `brief`（截断，约 280 字/买家） |

**没有别的参数。** 判不准时用 `full`，不要指望有个关键词参数帮你过滤。

返回每家：`买家名称` · `业务标签` · `业务说明` · 名下每条需求的
`需求名称` · `业务标签` · `要买什么业务` · `排除方向` · `地域说明` · `买家产业优势`。

「排除方向」要读：那是买家明确说不要的东西，命中了就不该推。

## 接口二 `get_buyer`

| 参数 | 类型 | 说明 |
|---|---|---|
| `name` | 字符串 | 买家名称，模糊匹配，认曾用名与别名 |
| `buyer_party_id` | 字符串 | 精确 id，从接口一或接口三的返回里拿 |

两个给一个即可。名称命中多个时返回全部候选，由你消歧。

返回买家主体全量 + 名下全部需求的完整档案（含原始需求正文，已清洗过重复段落）。

## 接口三 `filter_buyers`

买家自身条件（**它是谁**）：

| 参数 | 说明 |
|---|---|
| `ownership_type` | `state_owned` 国企 / `private` 私企 / `foreign` 外企 / `other` |
| `listed_status` | `listed` / `unlisted` / `pre_ipo` |
| `province` `city` `district` | 买家所在地，三级独立生效，填全称（江苏省 / 苏州市） |
| `min_market_cap_yuan` `min_revenue_yuan` | 买家自己的市值/营收下限，单位元 |

标的事实（**反查需求门槛**，传这个标的的真实数字）：

| 参数 | 说明 |
|---|---|
| `target_revenue_yuan` | 标的营收，单位元。会去比每条需求的「最低营收」 |
| `target_net_profit_yuan` | 标的净利润，单位元 |
| `target_pe` | 标的 PE，**倍数**，15 倍写 15 |
| `target_market_cap_yuan` `target_valuation_yuan` | 标的市值 / 估值，单位元 |
| `target_listed_status` | `listed` / `unlisted` / `pre_ipo` |
| `target_province` `target_city` `target_district` | 标的所在地，全称 |

**上限 50 条**。超出时会返回命中总数并提示收窄 —— 看到那句提示就说明还有没返回的，
不要当成「库里就这么多」。

返回里的 `notes` 会告诉你「只差一条就能命中的有哪些、去掉它能多召回几家」，
那是你放宽条件的依据。

## 地区怎么填

接口只认**标准行政区划全称**：`江苏省` `苏州市` `吴中区`。

**「长三角」「大湾区」「华东」这类说法要你自己展开成省份再传。** 参考：

- 长三角 = 上海市 / 江苏省 / 浙江省 / 安徽省
- 大湾区、粤港澳 = 广东省（+ 香港、澳门）
- 京津冀 = 北京市 / 天津市 / 河北省
- 成渝 = 四川省 / 重庆市

（买家侧材料里的大区在**写入时**已经由系统展开过了，所以库里存的是省份。
你查询时也要给省份。）

## 闸门

工具已经替你排除了：需求级别 `E` 的、状态是「结束推荐」的、主体不是在库状态的。
**状态是「暂停推荐」的会返回但带标注** —— 那条需求还在，只是暂时停了，
推荐前跟顾问确认一下。
