## 本包的权威数据流

```text
当前需求快照
→ 每个条件组先做完整真实初筛
→ 主 Agent 根据真实召回信号决定是否放宽
→ 每次初筛仍独立返回真实前 20，SQL 不排除前批 ID
→ 所有非 count_only 批次按 ID 求并集
→ 去重后最多 40 家进入一次深评
→ 深评结果回到主 Agent
→ 主 Agent 再做无工具收尾
```

“最终名单”不是代码固定取深评前 5。本包只负责让 Agent 看见深评结果并具备收尾能力；
最终 3–6 家的严格输出归一和 brief v2 在 4C 完成。

## 必须实现的四块

### 1. 代码强制的条件组与放宽策略

建议按总施工单新建叶子模块 `backend/app/services/recommendation_agent_policy.py`，用纯函数负责条件组编译、
调用校验和候选池汇总，避免把策略继续堆进 handler 或让叶子服务反向 import handler。

`search_targets` 增加 `group_id`；发生放宽时还必须有 `relaxation_reason` 和
`based_on_call_index`。代码而非 Prompt 必须保证：

- 每组第一次非 `count_only` 真实查询使用完整基线条件；
- 字段只能来自该组；不同组不能拼接；fallback 空组不能编条件；
- preferred 优先允许移除；
- required 通常不放宽，但在真实召回过少并有依据时可由 Agent 判断放宽；
- required 的数值只能单向放宽：`min_*` 降低、`max_*` 提高；
- 排除项永不放宽，由代码强制注入；
- 无效调用返回结构化错误、写 trace，并按施工单建议计入工具预算。

required 不是永不放宽的硬锁，也不是 Agent 可以无依据删除的软建议。每次放宽都要能追溯到此前真实查询的
召回量或 `excluded_by_condition` 信号，Writer 后续还需要区分完整命中与放宽补充。

### 2. 多批次真实结果求并集，最多 40 家公平收口

- 每次 SQL 查询独立返回最多 20 家；绝不能在 SQL 中排除前批已出现 ID；
- `count_only` 只试探，不形成候选；
- 保存每个真实批次的原始 ID 顺序和来源；
- 深评前才对所有真实批次按 ID 求并集；
- 示例必须成立：3 次各 20 家、共 30 条重复，去重后 30 家全部进深评；
- 并集超过 40 时按不同 `group_id` 公平轮询，同组多个批次再按调用先后轮询；不能按调用顺序简单截断；
- trace 记录 `raw_occurrences / unique_before_cap / unique_after_cap / capped`。

候选来源不要只留一个含义模糊的 hit count。维护 `matched_group_ids`、`matched_search_call_ids`、
`screening_hits`，并区分：

- `group_hit_count`：命中过几个不同需求组，是深评强信号；
- `search_hit_count`：在多少次查询出现，只作稳定性解释。

同一组完整筛与放宽筛都命中只能算一个 group hit。

### 3. 把深评改成受控工具并回灌主 Agent

新增 `deep_evaluate_candidates` 受控工具，不让模型传业务参数；executor 内部持有快照和候选池。
它最多调用一次，成功或失败后都冻结筛选阶段。返回深评状态、`ranked / dropped / uncovered`、
逐条定性判定、风险/信息缺口、筛选来源与候选池计数。

- 没有真实候选时不能调用；
- 深评结果必须回到主 Agent，不能在 handler 旁路跑完后让 Agent 看不见；
- Agent 忘调时，代码自动补跑一次，再给 Agent 一次无工具收尾；
- `unavailable/schema_mismatch` 不终止本轮，也不伪装成 ok；允许用 SQL 初筛顺序降级收尾；
- 用户中止优先，深评前后中止均不得继续生成最终 brief。

### 4. Prompt 版本收口

- `recommendation_deep_eval_to_target` 发布目标升级为 **v0.3.1**：在 v0.3.0 上加入逐家
  `full_conditions / relaxed_fields / screening_hits`，不得把放宽候选写成满足原 required；

- 复用现有节点，不新建节点；Prompt 走 API，不写 seed 迁移；
- 发布脚本要可审计、变量集合一致、同版本内容冲突明确失败。
