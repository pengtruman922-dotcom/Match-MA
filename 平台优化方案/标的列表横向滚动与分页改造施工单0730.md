# 标的列表横向滚动与分页改造施工单（0730）

对应页面：标的管理（`/targets`）→ `frontend/src/pages/Targets.tsx`。**本单只改标的页**；买家需求列表在 1440 下不横滚，暂不引入限高。

## 一、问题与实测

1440×1000 视口、20 行实测：

| 指标 | 标的管理 | 买家管理（对照） |
|---|---|---|
| 列数 | 20 | 9 |
| 表格宽 | **2404px** | 1375px |
| 容器宽 | 1375px | 1375px |
| 横向隐藏 | **1029px（43%）** | 0（1280 下 153px） |
| 表格总高 | **1733px** | — |
| 需下翻多少才够到横条 | **979px** | — |

即：43% 的列在屏幕外，而要够到横向滚动条得先下翻近 1000px；翻下去后表头已滚出视口，**拖横条时看不到列名**。后者在 20 列表格上比前者更致命。

## 二、范围

- 表格区独立限高滚动 + 表头吸顶（方案 C）。
- 每页条数 20/50/100。
- 分页器页码选择弹层（含直接输入页码）。
- 解析轮询请求数与每页条数解耦。

不做：列显隐配置（治本方案，工作量另计）；买家页同步改造。

## 三、表格区限高 + 表头吸顶

容器：`max-h-[calc(100vh-260px)] min-h-[400px] overflow-auto`。

- 260px = 顶栏 56 + 导航 44 + 页标题 60 + 工具栏 80 + 分页 48 + 边距，取整。
- `min-h` 兜底，避免 1366×768 这类小屏只剩两三行。

`thead th` 增加 `sticky top-0`。

### 坑 1：`border-collapse: collapse` 下 sticky 表头边框消失

实测当前表 `border-collapse: collapse`（Tailwind preflight 默认）。该模式下 sticky 元素的 border 不会跟随粘滞，滚动时表头下边框消失。

**改法**：表头行去掉 `border-b`，改用 `shadow-[inset_0_-1px_0_theme(colors.gray.200)]` 画下边框。

### 坑 2：z-index 需要四层

当前层级混乱且不足（`th` 有 z-30/z-20，`td` 有 z-20/z-10）。加上吸顶表头后必须重排：

```
普通 td                     auto
sticky 左/右列 td            z-20
普通 th（吸顶）               z-30
sticky 左/右列 th（四角交叉）  z-40
```

漏掉第 4 层时，横滚过程中表头的冻结列会被表体的冻结列盖住。

## 四、每页条数 20/50/100

后端三个列表接口均为 `limit: int = Query(default=50, ge=1, le=200)`，**20/50/100 全部不需要后端改动**。

- `TargetFilters` 增加 `pageSize`；URL 参数名 `pageSize`。
- 取值优先级：**URL 参数 > localStorage(`targets.pageSize`) > 20**。写入 URL 的同时写 localStorage。
- 非法值（不在 20/50/100 内）回落到 20。
- 切换条数时 `page` 重置为 1。
- `updateFilters` 用 `new URLSearchParams(searchParams)` 起手，只覆盖 patch 中的 key，因此翻页、改筛选、搜索都会原样带着 `pageSize`（已验证 `Targets.tsx:68-84`）。

## 五、分页器改造（`components/PaginationFooter.tsx`）

该组件被标的、买家需求、买家主体三个列表共用。新增能力全部**可选**：不传对应回调时渲染保持现状，买家页后续可直接接入而无需返工。

```
【关闭态】
┌──────────────────────────────────────────────────────────────┐
│  第 7 / 15 页 · 每页 [ 20 ▾ ] 条           [ 上一页 ][ 下一页 ] │
│  └──── 点这里 ────┘                                           │
└──────────────────────────────────────────────────────────────┘

【点击后：向上弹出，列表可上下滑动，当前页自动居中并高亮】
               ┌────────────┐
               │ 跳至 [   ] │ ← 直接输入页码，回车跳转
               ├────────────┤
               │     4      │
               │     5      │
               │     6      │
               │ ▓▓  7  ▓▓  │ ← 当前页：打开瞬间滚到居中 + 高亮
               │     8      │
               │     9      │
               │    10      │
               └────────────┘
┌──────────────────────────────────────────────────────────────┐
│  第 7 / 15 页 · 每页 [ 20 ▾ ] 条           [ 上一页 ][ 下一页 ] │
└──────────────────────────────────────────────────────────────┘
```

实现沿用仓库既有套路（`UpdateEntryMenu.tsx` / `ScenarioBadge.tsx`）：`createPortal` + `position: fixed` + 透明遮罩点击关闭。弹层向**上**弹（分页器在表格底部）。列表 `max-h-60 overflow-y-auto`，打开时 `scrollTop = (page-1)*itemH - containerH/2 + itemH/2` 实现居中。

> **实施中发现的坑**：沿用 `UpdateEntryMenu` 的 `window.addEventListener('scroll', close, true)`（capture 阶段关闭弹层）会与居中定位打架 —— `useLayoutEffect` 里设 `listRef.current.scrollTop` 本身就触发 scroll 事件，被 capture 监听捕获后弹层**打开瞬间就自己关掉**。已改为：scroll 事件源在弹层内部时不关闭（`menuRef.current.contains(event.target)`）。`UpdateEntryMenu` 不设 scrollTop 所以没暴露过这个问题。

> **范围说明**：每页条数下拉是可选 prop（只有标的页传），但**页码选择弹层对三个列表都生效**（组件内无条件渲染）。理由：它不改变布局、不增加请求、`pageCount <= 1` 时自动禁用，是零成本改进。若希望也做成 opt-in，加一个可选 prop 即可。

## 六、轮询与每页条数解耦

现状 `Targets.tsx:126-153`：每 4 秒对当前页**每一个**解析中的标的各发一次 `GET /seller-targets/{id}`。

| 每页 | 解析中行数上限 | 每 4 秒请求数 |
|---|---|---|
| 20（现在） | 20 | 20 |
| 100（改后） | 100 | **100** |

**改法**：每轮最多轮询 20 个，并在轮次之间轮转窗口（第 1 轮前 20 个，第 2 轮下 20 个，循环）。请求数钉死在 20/轮，与每页条数解耦，所有行最终都会更新到。

## 七、验收用例

1. 1440×1000 下打开标的列表，横向滚动条在表格容器底部**直接可见**，无需下翻页面。
2. 横向拖动时表头始终可见，且表头的冻结列不被表体冻结列遮挡。
3. 纵向滚动表格时表头吸顶不动，表头下边框不消失。
4. 切换每页条数到 100，URL 出现 `pageSize=100`；翻页、改筛选、搜索后该参数仍在。
5. 刷新页面保持 100；关闭标签页重新进入（URL 无参数）时仍是 100（localStorage 生效）。
6. 点击「第 X / Y 页」弹出页码列表，当前页居中高亮；点击任一页码跳转并关闭；输入页码回车跳转；越界输入被钳制。
7. 每页 100 且有 >20 个标的在解析时，每 4 秒的请求数不超过 20，且多轮之后所有解析中的行都能刷新到最新状态。
8. 买家需求列表与买家主体列表的分页器外观和行为不变。
