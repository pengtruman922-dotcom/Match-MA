## 本包必须完成的结果

### 1. 先修阶段三 Prompt 未闭环的 P0

生产中 `recommendation_deep_eval_to_target` 的默认 `v0.2.0` 仍是旧 schema，
而阶段三代码期待 `ranked / dropped / qualitative_requirements_json`，因此当前深评会落到
`schema_mismatch`。不要继续复用冲突的 v0.2.0。

- 新建 `scripts/publish_deep_eval_v030_prompt.py`；
- 使用阶段三新形态 Prompt 与 `ranked / dropped` schema，版本为 `v0.3.0`；
- 四个变量必须与 NodeSpec 完全一致；
- 同版本已存在且正文/schema 不同时必须明确报错并非零退出，不能无声 skip；
- 提供并验证 `--render-preview`；
- 不写 Prompt seed 迁移，不新建深评节点；
- `v0.3.0` 是 4A 的过渡收口，4B 会升级为含筛选来源的 `v0.3.1`。

未经用户明确许可，只能做本地检查、只读核查和 render-preview，**不要 `--apply` 修改生产 Prompt**。

### 2. 最近 5 轮问答进入需求解析

把 `recommendation_flow.AGENT_HISTORY_MAX_TURNS` 从 6 改为 5，并保持现有历史不变式：

- 只取已完成轮次；中止轮不带、不计数；
- 每轮同时带用户问题和 AI 最终正文原文；
- 工具消息、brief、`agent_step`、`agent_understanding`、`agent_deep_eval` 不进历史；
- 超字符预算时从最旧完整轮开始丢，绝不截断半轮；
- 继续使用明确的历史、用户和 AI 边界。

这里的“当前需求快照”不是代码把条件机械累计起来。需求解析 Agent 要读取最近 5 轮完整问答与本轮消息，
自主判断用户此刻的完整需求。

### 3. 需求解析 Prompt 升级到 v0.3.0

复用 `recommendation_query_parser`，不新建节点。Prompt 必须要求：

- 输出用户经过本轮表达后“现在要什么”的完整快照，而不只是本轮增量；
- 能结合历史判断保留、替换、删除和整体重置；
- “其他不变”保留历史明确条件；“去掉某限制”只删除指定条件；“重新找/重来”允许重置；
- 不补用户没表达过的条件；
- `raw_text` 仍由代码回填本轮原话，只作审计字段。

新建受版本控制的 v0.3.0 发布脚本并验证变量集合。Prompt 走 API，不写数据库迁移。

### 4. 把快照注入主 Agent

在现有 `recommendation_context_json` 中增加 `intent_snapshot`，至少包含：
`condition_groups / qualitative_requirements / exclusions / unstructured_notes / parser_status`。
历史仍走独立 `history_context`，不要塞进 JSON，也不要新增 Agent 节点变量。

失败语义必须明确：

- `parser_status=ok` 时，快照是主 Agent 的唯一结构化需求基线；
- `fallback/schema_mismatch` 时，结构化组为空，本轮原话进入定性兜底；
- 主 Agent 不得在解析失败后自行编造结构化条件；
- 失败不中断本轮，仍落 `agent_understanding` 和 trace；
- 解析后若用户已中止，不进入工具循环。
