## 验收的最终链路

逐段用代码、消息落库和测试证明以下链路真实成立：

```text
最近 5 轮用户问题 + AI 最终正文 + 本轮消息
→ 需求解析 Agent 输出本轮完整当前需求快照
→ 主 Agent 按条件组多次独立初筛并依据真实召回信号判断放宽
→ 所有非 count_only 真实结果按 ID 求并集，最多 40 家公平收口
→ 深评最多一次并把结果回灌主 Agent
→ 主 Agent 从 ranked 中选择 3–6 家重点名单及最多 5 家备选
→ brief v2
→ Writer 流式正文 + 独立追问芯片
```

重点口径：

- 当前需求快照由需求解析 Agent 结合最近 5 轮完整问答判断，不是代码机械累计；
- 每次初筛独立返回真实前 20，不能为了多样性在 SQL 中排除前批 ID；
- 3×20 且有 30 条重复时，去重后的 30 家全部进入深评；
- required 通常不放宽，但 Agent 可以在召回太少且有真实依据时单向放宽；排除项永不放宽；
- 深评结果必须回到主 Agent，最终名单不是代码固定取前 5；
- 追问建议只在芯片中，不写进正文。
