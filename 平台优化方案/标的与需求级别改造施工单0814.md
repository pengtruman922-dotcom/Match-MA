# 标的与需求级别改造施工单（0814）

用「级别 A–E」替代标的的交易状态与买家需求的推荐状态。`E` = 不进推荐（标的已售出/已停售，需求暂停推荐/结束推荐），`A–D` = 推荐中。

对应实体：`seller_target`、`buyer_intent`。

## 一、目标与决策

### 1.1 数据模型：两列并存，一条不变式

级别是新的唯一闸门；原状态列**保留**，降级成「`E` 的细分原因」。两列双向绑定：

```
seller_target:  target_grade ∈ {A,B,C,D}  ⟺  lifecycle_status = 'active'
                target_grade = 'E'        ⟺  lifecycle_status ∈ {sold, off_market}

buyer_intent:   intent_grade ∈ {A,B,C,D}  ⟺  status = 'active'
                intent_grade = 'E'        ⟺  status ∈ {paused, closed}
```

**不变式写成 DB CHECK 约束，不靠写入方自觉。** 理由在 `005_target_status_consolidation.sql` 的注释里：上一个「一列答两个问题」的字段（`recommendation_status`）就是因为只有一条窄路径会正确置位，其余路径静默留在错误值上，生产上 8 个活跃标的因此长期从推荐里消失。两列耦合比一列多义更容易漂，约束是唯一能保证「不可能出现 `grade='A'` 但 `lifecycle_status='sold'`」的东西。

界面上因此可以只放一个下拉，不做两步选择：

| 实体 | 下拉选项 |
| --- | --- |
| 标的 | A ／ B ／ C ／ D ／ E（已售出）／ E（已停售） |
| 买家需求 | A ／ B ／ C ／ D ／ E（暂停推荐）／ E（结束推荐） |

列表徽标：`A`–`D` 只显示字母，`E` 显示 `E（已售出）` 这类复合标签。

### 1.2 写入规则

| 路径 | 规则 |
| --- | --- |
| 新建实体 | 默认 `C`。建表 `default 'C'` + 创建接口默认值，创建时**不允许**直接给 `E` |
| AI 解析 / 业务更新 | 材料明确给出级别或明确表示停售/停推时才写；未提取到就不写。**只能进 `E`，不能出 `E`** |
| 人工（详情页下拉） | 任意方向，出 `E` 时必须显式选一个 `A–D` |
| 关系推进到 `deal_closed` | 标的置 `E（已售出）` |

**「AI 不能出 E」是沿用现有不变式**，不是新规定：`extracted_action_apply.py` 原注释即为 *"A later in-sale signal never reactivates a sold or off-market target automatically."* 这样也顺带回答了「E 之前是 A 级，恢复时记不记得」——不记得，由人重选。

**`E` 未带原因时的默认**：标的 `off_market`（已停售）、需求 `paused`（暂停推荐）。取弱的一侧：模型只会在材料说「不再推荐」但没说为什么时输出裸 `E`，说了「已售出」会被中文词映射直接接住。默认成「已成交」是凭空声称一笔交易，默认成「已停售」不损失任何信息。

### 1.3 两个必须避免的反模式

**① 解析 handler 里不要写兜底默认值**

```python
changes["target_grade"] = extracted or "C"   # ← 禁止
```

这一行会让每次重新解析把人工设成 `D` 的标的打回 `C`。「默认 C」只在实体创建这一个点生效，解析路径一个兜底分支都不要有。

「未提取到就不写」本身是白拿的：`field_writer.write_seller_target_fields` 只处理 `changes` 里实际出现的键，且只写真实 diff。不加兜底即可成立。

**② 提示词里不要出现「默认 C」**

模型能看到该字段当前值（词汇表同时是 SELECT 投影）。提示词里只要出现「未提及则默认 C」，模型每次解析都会主动吐一个 `C`，人工设的 `A/B/D` 当场被覆盖。提示词只写一句：

> 仅当材料明确给出级别（A/B/C/D）或明确表示已售出/已停售/暂停推荐/结束推荐时，才输出该字段；否则不要输出这个字段。

### 1.4 范围

**做**：DB 两列 + 约束 + 回填；级别派生单点；四处推荐闸门；两侧读写链路；前端展示与筛选口径；提示词。

**不做**（本单明确排除）：

- **A–D 对推荐排序/打分的影响**。本单只做「E 不进筛选」，`A–D` 之间完全不影响召回与排序（注册表里不设 `screening` / `deterministic_rank`）。
- **筛选功能本身的改造**（另议）。本单只保证列表筛选参数换到新列后能正常工作。
- **`deep_eval_grade` 的 A/B/C**。该套逻辑将被单独废弃，本单不动它，但**不要和本单并到同一次发版**，否则两个 A/B/C 同时变动无法定位问题。
- **phase B 删旧列**。本单只到 phase A（加列 + 双写），删列另开迁移。

## 四、级别派生单点

新建 `backend/app/services/entity_grade.py`。所有写入方都调它，**不允许任何地方自己拼 grade 与原因列的组合**。

```python
@dataclass(frozen=True)
class GradeSpec:
    grade_column: str
    reason_column: str
    active_reason: str
    default_e_reason: str
    e_reasons: frozenset[str]

SELLER_GRADE = GradeSpec("target_grade", "lifecycle_status", "active", "off_market",
                         frozenset({"sold", "off_market"}))
BUYER_GRADE  = GradeSpec("intent_grade", "status", "active", "paused",
                         frozenset({"paused", "closed"}))

def resolve_grade_pair(spec, changes, current, *, allow_reactivation) -> dict[str, str]:
    """把一批变更里的级别列与原因列收敛成一致的一对。"""
```

行为：

1. 两列都没出现在 `changes` 里 → 返回 `{}`（不写）。
2. 只给了原因列（沿用现有中文词映射的产物）→ 由原因推级别。
3. 只给了级别 → 由级别推原因；`E` 且当前原因不是 `E` 类原因时用 `default_e_reason`。
4. 两个都给了但矛盾 → **以级别为准**，原因按第 3 条重算。
5. `allow_reactivation=False`（AI 写入）且当前已是 `E`、目标不是 `E` → 返回 `{}`，静默不动（保留现有「AI 只进不出」不变式）。
6. 非法级别值 → 返回 `{}`，由调用方按各自的 `rejected_fields` 约定记录。

`allow_reactivation`：AI 路径 `False`，人工路径 `True`。

## 十二、实施记录与偏离（2026-08-14 落地）

本地已完成 §二~§八与 §十，`955 passed`（新增 `tests/test_entity_grade.py` 23 条）、前端 `tsc --noEmit` 与 `eslint` 均通过。§九的提示词与 §十一的发布未做。

**偏离 1 · 筛选分桶只按级别，不按 E 的原因拆。** 原计划让 `SELLER_TARGET_DISPLAY_STATUS_SQL` 产出 6 个带原因的桶。实施时改成 5 个（A/B/C/D/E）：筛选的单位是级别，「为什么退出推荐」是行内徽标和详情页的事，拆成两个 `E` 桶会让筛选值不唯一。连带把 `SELLER_TARGET_DISPLAY_STATUS_SQL` 与 `SELLER_TARGET_DISPLAY_STATUS_LABELS` 两个常量删掉了——那段 `case` 退化成一个列名之后，常量只是多一层间接。

**偏离 2 · 创建接口不再接受交易状态。** `SellerTargetCreate.lifecycle_status` 直接被 `target_grade: Literal["A","B","C","D"]` 取代（默认 `C`）。建标的时就「已售出」没有意义，且留着这个入参就等于留了一条绕过不变式的路。真要建成 `E` 由详情页改。

**偏离 3 · 中文枚举映射要单独开分支（施工单漏了）。** `lifecycle_status` 进注册表后会进入 `writable_enum_values()`，于是业务更新阶段的通用归一化 `_normalize_enum_value` 会先把它小写化再比对闭集——「已售出」当场被判非法丢弃，`_lifecycle_status_from_changes` 根本看不到。修法是在 `_normalize_field_value` 加两个 per-field 分支（级别要保大写、lifecycle 走专表），中文映射表搬到 `entity_grade.LIFECYCLE_STATUS_ALIASES` 由两处共用。通用的 `ENUM_VALUE_ALIASES` 装不下它：「已成交」在关系状态里是 `deal_closed`、在标的这里是 `sold`。

**偏离 4 · `pause_reason` 继续对模型隐藏。** 施工单说买家侧排除表放行 `status`，实施时只放行了 `status` 与 `intent_grade`，`pause_reason` 留在排除表里——它是自由文本，塞进上下文只会诱导模型原样回吐当前值。

**偏离 5 · 测试守卫的正则要认大写。** `test_indicator_registry._constraint_value_sets` 只匹配 `'[a-z_]+'`，级别是 `'A'`–`'E'`，会把 017 的约束读成空集、误报「注册表枚举 DB 不接受」。已放宽到 `[A-Za-z_]`。
