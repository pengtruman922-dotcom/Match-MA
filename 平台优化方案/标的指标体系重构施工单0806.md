# 标的指标体系重构施工单（第一轮：只动标的侧）

> 2026-08-06。上游是 `标的指标体系重构结论0805.md`（判决）与顾问的真实需求问卷（上市 11 项 / 非上市 10 项）。
> 本文件只管**第一轮的施工范围与边界**。结论文档里排在本轮之外的条目，本文件逐条列出「为什么不做、什么时候做」，不重复论证。

---

## 一、范围铁律

**本轮只动两个功能面，其余一律不碰：**

1. **标的管理模块 — 标的信息**（读、显示、手动编辑）
2. **标的新建 / 标的信息更新的 AI 节点**（解析链路）

**绝对不动筛选与打分代码。** `recommendation_flow.py`、`recommendation_agent_tools.py` 本轮**一行不改**——包括它们手写的 SELECT 投影。新列不进那两个 SELECT 完全没关系，打分器本来就不读它们。

范围翻成文件：

| 面 | 文件 |
|---|---|
| 标的信息 | `backend/app/api/routes/seller_targets.py`、`backend/app/registry/indicators.py`、`backend/app/api/routes/update_logs.py`、`frontend/src/types/api.ts`、`frontend/src/lib/fieldLabels.ts`、`frontend/src/features/targets/infoGroups.ts`、`frontend/src/features/targets/TargetInfoPanel.tsx` |
| 标的 AI 节点 | `backend/app/jobs/handlers/seller_target_parse.py`、`backend/app/jobs/handlers/common.py`、`backend/app/services/extracted_action_apply.py`、`backend/app/services/business_update_flow.py` + 三个 prompt 版本 |
| schema | `database/migrations/015_target_risk_and_structure_facts.sql` |

**多带一个节点**：`business_update_extractor`（`nodes.py:368`）是业务更新的兜底解析——同时绑定标的与买家、或两者都没绑定时走它，也会写标的字段。只改两个专用节点会让走兜底路径的更新填不上新字段，且这种漏填时灵时不灵，最难查。三个 prompt 一起改。

## 二、本轮做什么

### 2.1 新增 4 个标的侧列

| 列 | kind | 归类 | writable_by | 说明 |
|---|---|---|---|---|
| `major_risk_flags_json` | json（多值枚举） | 可枚举定性 | parse / research / manual | 问卷第 6 项 |
| `acceptable_transaction_structures_json` | json（多值枚举） | 可枚举定性 | parse / manual | 问卷第 7 项 |
| `main_products_text` | text | 不可枚举定性 | parse / research / manual | 行业只到 L2，产品层缺失 |
| `stock_code` | text | 非指标（核验） | parse / research / manual | 展示用 |

**重大风险闭集**（两侧共用，买家侧下一轮建）：

| code | 中文 |
|---|---|
| `litigation` | 涉诉 |
| `equity_frozen` | 股权冻结 |
| `enforcement` | 被执行 |
| `violation` | 违规违法（行政处罚 / 立案） |
| `none` | 已核查，无重大风险 |

**空数组 = 未核查，`["none"]` = 已核查无风险。这两个状态必须分开**——一个字段三种状态表达完，不需要第二个字段。乐观三态在这个维度上会把「没查过」当成「干净」，是唯一一处该偏离默认的地方；但**偏离发生在打分器**，本轮不做，先把事实列建起来。

`risk_summary` 保留为**明细载体**（哪个案子、金额多少、进展如何），枚举是它的可筛选投影——与 `industry_pairs_json` 和画像栏的关系完全一致。

**交易结构闭集**（顾问问卷第 7 项「交易方式（多选）」，2026-08-06 确认按此定稿）：

| code | 中文 |
|---|---|
| `equity_transfer` | 股权转让（老股） |
| `capital_increase` | 增资扩股（新股） |
| `asset_purchase` | 资产收购 |
| `merger` | 吸收合并 |
| `other` | 其他 |

它与控股维度（`can_control` / `can_consolidate` / `accepts_minority_investment`）**正交**：增资扩股可以控股也可以参股，股权转让同理。两个维度都要留，不能互相派生。

### 2.2 删 `operation_stability_status`

伪枚举：「稳定 / 不稳定」没有客观判据，同一份材料两次解析可以给出不同值；买家也不用这个词提要求。读者全部落在本轮范围内（`seller_targets.py`、`update_logs.py`、`seller_target_parse.py`、`fieldLabels.ts`），删得干净。内容归 `ops_quality` 画像栏。

### 2.3 `financial_period_end_date` 开 parse 写入

它的 `writable_by` 只有 `research`，而解析是标的的主要入口——于是「防止旧期覆盖新期」「同期冲突判定」对解析写入的数据全部失效。改一行 + 解析 prompt 里要求同时给出 `financial_period_label`（展示原话）与 `financial_period_end_date`（ISO 日期）。

### 2.4 收敛标的域的 SELECT 投影

`seller_target` 的事实列清单以前有 6 处手写，加一列要逐个改，漏一处的表现是「字段存进去了但某个页面看不见」，最难查。本轮把清单收敛到注册表派生的**一个函数**，改 4 处调用点 + 1 处回滚白名单：

`seller_targets.py` / `seller_target_parse.py` / `extracted_action_apply.py` / `business_update_flow.py` / `update_logs.py`。

**推荐域的 2 处（`recommendation_flow.py:1202`、`recommendation_agent_tools.py:363`）保持手写，本轮不动**——收敛它们要改推荐文件，越界。

### 2.5 统一「技术与团队」命名

注册表叫「技术与团队」，画像栏叫「技术与团队能力」，同一块东西两个名字。

## 四、调研节点会自动接手（已确认按此执行）

`major_risk_flags_json` 与 `main_products_text` 的 `writable_by` 含 `research`，`research_map.py:236` 会**自动**把它们加进调研字段目录（含 `allowed_values`），**零代码改动**。

后果是标的 AI 调研节点的行为会变：开始产出风险与产品字段的提案。这是有意为之——风险核查靠的是工商公开信息，正是调研 Agent 最擅长的；存量标的的风险字段只能靠调研回填，不开就得人工一条条填。

## 五、验收标准（重要）

**做完之后推荐结果不会有任何变化。** 4 个新列在买家侧没有对手方、在打分器里没有维度。本轮的产出只有两样：

1. 标的信息页能看、能编、能显示这 4 个字段；
2. 解析（三个节点）与调研能把它们填上。

**验收就按这两条走，不要拿「推荐变准了」验收。** 业务价值要等下一轮接线才兑现。这个顺序是对的——先攒事实，再建配对，接线时已有存量数据可用。

## 七、施工顺序

1. 迁移 `015`（加 4 列 + check + GIN 索引，删 `operation_stability_status`）→ 跑 `tests/test_migration_sql.py`
2. `indicators.py`：加 4 个指标、删 1 个、`financial_period_end_date` 开 parse
3. 解析归一化：`CLOSED_LIST_FIELD_VALUES` 改为从注册表派生（现在是买家侧手写的两项），让标的侧多值枚举列自动获得同样的「字典外取值丢弃」保护
4. 收敛 SELECT 投影（4 处调用点 + 回滚白名单）
5. API 模型（`SellerTargetOut` / `SellerTargetUpdate`）+ 前端类型、标签、json 多值枚举的展示与多选编辑器
6. 更新 `tests/test_indicator_registry.py`（新列不在 baseline，需认 015 迁移）→ 跑全量 pytest
7. 设置页发布三个 prompt 新版本（即时生效，不发版）

第 7 步不在代码里。枚举取值**不会**自动注入 seller 侧 prompt（买家侧 `buyer_intent_parse.py:475` 会，seller 侧不会），所以新枚举必须手动写进三个提示词，否则模型不知道这些字段存在，字段建了也永远为空。

## 八、三个提示词的改动（设置页操作，不发版）

对照生产上当前生效的版本：`seller_target_parser` v0.9.0、`seller_target_update_parser` v0.3.2、`business_update_extractor` v0.11.1。三个都在设置页「Prompt 版本管理」新建版本，保存即生效。

### 8.1 三个提示词都要加的一段（追加到 Rules / 字段规则末尾）

```
新增标的字段（只在材料明确支持时输出，缺证据一律省略）：

- major_risk_flags_json：重大风险，数组，取值只能来自
  litigation（涉诉）、equity_frozen（股权冻结）、enforcement（被执行）、
  violation（违规违法，含行政处罚与立案）、none（已核查，无重大风险）。
  · 材料明确说明已核查且无上述风险时，输出 ["none"]。
  · 材料没有提到风险核查这件事时，**整个字段省略**，不要输出空数组 ——
    空数组的含义是「尚未核查」，那是一个结论，不能由「材料没写」推出。
  · 具体案由、金额、进展继续写进 risk_summary，两者并存：枚举用于筛选，
    risk_summary 是明细。
- acceptable_transaction_structures_json：标的方可接受的交易结构，数组，取值只能来自
  equity_transfer（股权转让/老股）、capital_increase（增资扩股/新股）、
  asset_purchase（资产收购）、merger（吸收合并）、other（其他）。
  与可控股/可并表是两件事：增资扩股既可以控股也可以参股，不要互相推断。
- main_products_text：主要产品或产品线，一行，400 字以内，只列产品/产品线本身
  （如「锂电池正极材料、隔膜」），不要重复 business_summary 的业务描述。
- stock_code：股票代码，照抄材料原文（如 "688981.SH"、"00700.HK"）。
  未上市标的省略该字段。
- financial_period_end_date：财务期间截止日，ISO 日期（YYYY-MM-DD）。
  与 financial_period_label 同时输出：label 照抄材料口径（如「2024年度」），
  end_date 是它换算出的截止日（2024年度 -> 2024-12-31，2025年上半年 -> 2025-06-30）。
  材料没有明确期间时两个都省略，不要拿处理日期充数。
```

### 8.2 `seller_target_update_parser` 额外要删的一行

```
- operation_stability_status 只能取 stable / unstable / unknown / needs_review。
```

该列已随迁移 `015` 判死。留着这行的后果是模型继续输出它，然后被写入白名单静默丢弃——不报错，但每次解析都在浪费 token 并在归一化日志里留下噪声。

### 8.3 顺手可做的清理（不做也不影响本轮）

- `seller_target_parser` 的 Rules 第 8 条仍在提 `raw_region_text`，该列已随迁移 `002` 删除；同一份提示词末尾的 R4 铁律又要求「never emit raw-region」，两句话互相打架。
- 三个提示词的输出样例里都还有 `gap_summary`。该列零写入、判死待办（§三），本轮不删列，所以提示词里留着不会出错，但下一轮删列时要一起清掉。
