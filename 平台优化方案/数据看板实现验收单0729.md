## 0. 先说四件必须知道的事

**(1) 底图是我下载的，来源与合规口径请你确认。**
文件来自 **DataV.GeoAtlas**（`https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json`，582 KB，
35 个 feature = 34 个省级行政区 + 南海诸岛九段线）。你在对话里明确授权了这次下载。
它**含台湾省与南海诸岛**，这是选它的原因。原始 GeoJSON **没有进仓库**，进仓库的是转换后的
SVG 路径（见 §2.2）；要换成自然资源部标准地图服务的矢量底图，重跑一次转换脚本即可，
前端代码不用动。

**(2) 后端端点没有在真实数据库上跑过。**
本机没有 Postgres，SQL 用了 `jsonb_array_elements`、`count(*) filter`、`cross join lateral`，
都是 PG 专有语法，sqlite 跑不了。**§4 的数字核对必须部署后做**，那是本轮唯一没有覆盖到的
风险面。

**(3) 二级行业榜单目前是偏的，这是已知的、我没能修的问题。**
你要求行业维度从一级改二级。生产数据里二级行业字典的同义词尚未合并，直接后果：

| 实际同一赛道 | 字典里的独立 L2 | 各自标的数 |
|---|---|---|
| 食品 | `食品` / `食品加工` / `食品制造` / `休闲食品` | 2 / 2 / 1 / 1 |
| 生物医药 | `生物医药` / `生物制药` | 1 / 1 |

合并后食品类共 6 个标的，本该与 `汽车零部件`（5）并列榜首，现在被拆成四行、最高的一行只有 2，
**在 top 10 里看起来无足轻重**。这不是取数写错了，是字典没去重——去重要「代码 + 迁移 + 存量
`industry_pairs_json` 回填」三件一起做，是独立工单（拆除验收单 §1.3 第 3 点已立）。
本轮的处理是**把这句话印在页面上**（行业面板脚注），而不是让人以为榜单是准的。

**(4) 买家地图数据很稀疏，这是你在我提出后仍决定要做的。**
27 个买家主体里 **15 个没填所在地**（56%），填了的 12 个散在 8 个省、单省最多 2 家。
所以这张图现在只有两种深浅、点亮 8 个省。我做了两件事让它不至于骗人：给买家配了独立的、
更密的分档表（1 / 2–3 / 4–6 / 7+），图例上直接写「未填所在地 15 家」。
**数据补上来之前，这张图的信息量就是这么多。**

## 2. 版面与三个设计决定

```
┌──────────────────────────────────────────────┐
│              标的省级分布（红）                 │   地图居中，最大宽 880px
├──────────────────────────────────────────────┤
│              买家省级分布（金）                 │
├───────────────────────┬──────────────────────┤
│   标的行业分布 top      │    标的营收规模        │   grid 默认 stretch，两块等高
└───────────────────────┴──────────────────────┘
```

页面不写标题也不写口径说明——导航上已经写着「数据看板」，口径属于文档不属于大屏。
右上角只有「更新于 …」和一个刷新图标；时间取**服务端** `now()`，不用浏览器时钟，
因为大屏可能整天不刷新，这一栏正是用来判断屏上的数还新不新的。

### 2.1 取数口径：全库 · 全部状态 · 全员可见

按你的选择。三条都写进了守护测试，因为它们都是「顺手对齐其它端点」就会被悄悄改掉的东西：

| 决定 | 为什么 | 守护测试 |
|---|---|---|
| 不按 `owner_scope` 过滤 | 按负责人过滤会让大屏上每个人看到的图不一样，看板就不再是同一张盘子 | `test_overview_is_not_owner_scoped` |
| 不按 `lifecycle_status` 过滤 | 已售出与已停售同样是存量的一部分 | `test_overview_counts_every_lifecycle_status` |
| 响应只出计数，不出名称 | 看板会当着客户的面打开 | `test_overview_returns_counts_only` |

软删除仍然排除——那是删掉的数据，不是卖掉的标的。

### 2.2 底图预处理放在离线脚本，不放运行时

`scripts/build_china_map.py` 做三件事，产出一个 TS 模块：

1. **Albers 等积圆锥投影**（中心经线 105°E，标准纬线 25°N / 47°N）。选等积不是审美问题——
   这是 choropleth，投影一旦放大北方省份，视觉上就等于放大了它们的占比。
2. **Douglas-Peucker 简化**（容差 0.35 输出单位）：25,222 个点 → 10,440 个，路径数据 130 KB。
3. **南海诸岛拆进插图**：纬度全部低于 17.8°N 的环 + 九段线 feature 归入插图，
   海南岛主岛（18.1°N 起）留在主图。这样一个省的几何被拆到两个框里，不需要维护省名清单。

**为什么不在运行时解析 GeoJSON**：那要么把 582 KB 原始文件打进包，要么写一份投影代码进前端。
离线做完，浏览器只见到 34 个 `<path d>` 字符串。两张地图共用同一个 chunk，只下载一次。

### 2.3 固定分档，且按指标各配一份

阈值硬编码而不是按当前最大值分位，是为了让**同一个颜色在两次打开之间含义不变**——
大屏上一个省从深色退成浅色应该意味着数量少了，而不是别的省多了。

但**两张图不能共用一张分档表**：买家主体总数不到标的的一半，单省最多 2 家，
套标的的「1–2 / 3–5 / 6–10 / 11+」会让整张买家图落在最浅一档，等于没有信息。
所以买家另配一份更密的「1 / 2–3 / 4–6 / 7+」，配色也从红换成金，避免两张红图叠在一起认错。
`test_buyer_map_has_its_own_tier_table` 盯着这一点。

**过程中发现并修掉的三个真问题**：

1. **插图框盖住台湾**。最初用绝对定位把南海诸岛浮在地图右下角，而主图 viewBox 是按省界紧贴
   裁出来的，右下角正好是台湾。改为把画布向右扩出一块空白再放插图。
2. **更新时间显示成 `-`**。我给 Postgres 的 `now()::text` 加了句"规范化" `replace(' ','T')`，
   结果 `2026-07-29T04:12:33.512+00` 被浏览器判为 Invalid Date（`+00` 缺分钟位），
   而原样的空格形式本来就认。仓库其它地方都是直接 `new Date(value)`，我多此一举。
3. **地图独占整行后被拉到一千多像素高**。中国地图接近方形，1400px 宽会按 737:620 拉高。
   给「图 + 图例」整块加了 880px 的居中最大宽度，两侧留白成为版面的一部分。

**登录说明**：验证时用的是假 token（`ProtectedRoute` 只检查 localStorage 里有没有值，
真实性由 API 把关），配合 stub 拦下该页唯一的请求。**没有使用也没有输出任何真实凭证。**

## 4. 部署后必须做的数字核对（本轮未覆盖）

端点的 SQL 一次都没在 Postgres 上执行过。部署后请求 `/api/v1/stats/overview`，
对照下表——这些是我本轮**从生产 API 逐条读出来的真实分布**：

| 路径 | 期望值 |
|---|---|
| `targets.total` | 60 |
| `targets.province_unknown_count` | 2 |
| `targets.provinces` 前四 | 江苏省 19、浙江省 9、广东省 7、山东省 3 |
| `targets.industries` 前三 | 汽车零部件 5、半导体 4、医疗器械 4 |
| `targets.industry_other_count` | 18（共 28 个 L2，减去 top 10） |
| `targets.industry_unknown_count` | 16 |
| `targets.revenue_buckets` | 5000万以下 0、0.5–1亿 8、1–3亿 16、3–5亿 8、5–10亿 3、10亿以上 8 |
| `targets.revenue_unknown_count` | 17 |
| `buyers.total` | 27 |
| `buyers.province_unknown_count` | 15 |
| `buyers.provinces` | 广东/上海/江苏/浙江 各 2，江西/山东/北京/湖北 各 1 |

对不上的两种可能：
- **`targets.total` 大于 60**：正常。60 是 `/seller-targets` 列表接口的可见数，`seller_target`
  表里有 108 行，差额是软删除的。若落在 60 和 108 之间且 `deleted_at` 已排除，说明列表接口
  另有过滤，不是本端点的问题——但要确认差额来源。
- **某个省份出现在页面的「与底图对不上」黄字提示里**：说明省份字段有非全称写法。
  页面会把它列出来而不是静默归零，按提示补齐数据即可。
