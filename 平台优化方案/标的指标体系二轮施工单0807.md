## 一、判据（生产实测，2026-08-07，70 个标的 / 44 个买家需求）

动手前把每个字段的填充率量了一遍。**这一轮删掉的东西，全部有实测支撑，不是审美判断。**

### 1.1 分组严重失衡

| 分组 | 字段数 |
|---|---|
| 身份与地区 | 4 |
| 业务与产品 | 3 |
| 技术与团队 | **2** |
| 经营质量 | 9 |
| 交易属性与出售诉求 | **25** |

43 个字段里，**7 个填充率 0%，13 个 ≤3%，真正撑起这一页的是 12 个（≥50%）**。

### 1.2 技术与团队整组接近空集

```
团队可留任   3/70   4.3%
管理团队     0/70   0.0%
```

两个字段命运不同：

- `management_retention_possible` **不能删**。它有活的买家对手方 `requires_team_retention`（团队留任要求，`screening=True`、`deterministic_rank=True`）。它是一对成对指标的标的侧，问题只是**放错了组** —— 对手方在买家的「交易与能力要求」里。
- `management_team_summary` **可以删**。0/70，只有 manual 可写，全仓引用只有 API 出参与前端标签一行：不进召回文档、不进深评 profile、不参与筛选打分。纯展示死列。

### 1.3 上市地在生产里完全空转

```
买家侧 44 个需求，listing_market_region 全部为 NULL
  → recommendation_flow.py:2641 那个 6 分打分维度从未触发过
标的侧 70 个，16 个有值，全部是 domestic，0 个 overseas
  → 只有一个取值在用，判别力为零
```

换枚举零数据损失。而且 `domestic` 反推不出交易所，本来也只能重来。

### 1.4 「业务与产品·其他」被写成了业务摘要的复述

比对 23 个同时有 `business_summary` 与该栏内容的标的：

| 相似度 | 个数 |
|---|---|
| >0.7 高度重复 | 2 |
| 0.4~0.7 部分重复 | 6 |
| <0.4 字面不同 | 15 |

字面不同的那 15 个，抽样看**是同一件事的另一种说法**：

```
摘要：公司主营有色金属（铝合金）高压压铸及机械加工，产品以汽车零部件为主…
其他：公司专业从事铝合金及铝合金精密零部件研发、生产和销售，产品线涵盖…
```

这一栏的提示语五栏共用一句「只写结构化字段装不下的定性判断」，没有一个字说明本栏该装什么。
所以「产业优势」这种内容会随机落位 —— 实测水晶光电的产业地位描述落在了「技术与团队·其他」。

### 1.5 深评今天看不到任何结构化字段

深评的候选载荷（`recommendation.py:806`）只有：

```
candidate_id / name / rule_score / recommendation_level / match_state /
matched_scenarios / matches / gaps / missing_dimensions / profile
```

`profile` = `render_profile_text(sections)`，**就是那 5 个「其他」框拼起来的一段文字**，空了才回落 search_doc。
标的的结构化列（营收、行业、上市状态、风险）一个都不进深评。
注册表上的 `Indicator.deep_eval` 标志**全后端零消费方**，只出现在 `/meta/indicators` 出参里（`meta.py:52`），前端也没读 —— 死配置。

**这条判据决定了产业优势的做法**：既然画像栏就是深评唯一的文字载体，
「产业优势」做成画像栏 = 零深评改动就自动进深评；做成新列 = 必须现在接一条列→深评的通路，
而那属于下一轮。**所以产业优势用栏目改名，不新建列。**

## 二、改动

### 2.1 上市地：境内/境外 → 具体交易所（买卖双侧）

**保留列名 `listing_market_region`**。改名要动 25 处（3 处 SQL 投影、对话条件契约、买家 API 模型、前端 4 处类型…），
而列名不出现在界面上；注册表加注释说明即可。

新闭集：

| value | 中文 |
|---|---|
| `sse` | 上交所 |
| `szse` | 深交所 |
| `bse` | 北交所 |
| `hkex` | 港交所 |
| `nyse` | 纽交所 |
| `nasdaq` | 纳斯达克 |
| `other` | 其他 |
| `unknown` | 未知 |

补 `unknown` 的理由：本仓所有枚举都留了它，它和 NULL 含义不同 ——
「查过但不确定在哪上市」vs「没查过」。信息页对两者都显示占位符（`infoGroups.ts` 有注释），
但打分与审计能区分。

**两侧都保持单值。** 「A股都行」= 上交所+深交所+北交所，单值 `eq` 表达不了，
但改多值要把 operator 换成 `overlap`，那是筛选契约，属于下一轮。买家侧现在 44 个全 NULL，不急。

**打分代码一行不动**：`recommendation_flow.py:2641` 是 `target == required` 的相等比较，
枚举换值逻辑不变。这也是「保留字段」相对「删字段」的全部收益。

### 2.2 解散技术与团队

- 删 `IndicatorGroup("tech_team", ...)`
- `management_retention_possible` 组改 `deal_terms`，与买家侧 `intent_deal` 对齐
- 删列 `management_team_summary`

### 2.3 「业务与产品·其他」改名「产业优势」

- `PROFILE_SECTIONS` 里 `business_product` 的中文名 `业务与产品` → `产业优势`，预算 400 → 600
- 删 `tech_team` 栏；`PROFILE_TOTAL_BUDGET` 1600 → 1500（200 + 600 + 300 + 400）
- `_clean_profile_content` 里过滤「股东」的 `tech_team` 分支迁到 `business_product`
  —— 那条规则（财务股东不是管理/研发团队）在新语义下同样成立
- `PROFILE_SECTION_ALIASES` 的 `chain_position → business_product` **保持不变**，
  而且语义反而变准了：产业链位置本来就是产业优势；
  同时新增 `tech_team → business_product` —— 提示词是设置页手工发布的，
  代码发版与提示词发布之间必然有一段错位期，这段时间模型仍按旧栏目输出，
  没有别名就会被当成未知栏目整段丢弃
- 前端「其他」块的标题改成按栏显示，`/meta/indicators` 的 group 增补 `section_label`

**新增 `PROFILE_SECTION_HINTS`（§1.4 的正解）**：每一栏该装什么，一份真源，
同时喂给信息页输入框的 placeholder 和提示词的栏目说明。
原来五栏共用一句「只写结构化字段装不下的定性判断」，这是产业优势随机落位的直接原因 ——
栏目改了名但提示语不改，问题只会换个地方复发。产业优势那条明写了
「不要复述业务摘要 —— 做什么生意是「业务摘要」字段的事」。

内容去向（用户拍板）：

| 原栏目 | 有内容标的 | 去向 |
|---|---|---|
| `tech_team` | 24 | **整段接管产业优势** —— 产能、资质、技术路线本来就是「优势」 |
| `business_product` | 26 | **整体作废**，不迁入 —— 内容是业务摘要的复述，迁进去会让新栏目一上线就变成「业务摘要 2 号」 |

作废用软删（`deleted_at = now()`），内容留在表里可回查，只是不再是当前值。
**注意**：迁移是裸 SQL，不经过 `apply_profile_section`，所以**不会写 `action_application_log`**
—— 顾问在「更新记录」里看不到这次作废，只能用 SQL 找回。这是已知取舍，不是遗漏。

### 2.4 删四个 0% 且无买家对手方的列

| 列 | 填充率 | 买家对手方 | 理由 |
|---|---|---|---|
| `management_team_summary` | 0% | 无 | 见 §1.2 |
| `transfer_flexibility_type` | 0% | 无 | 与 `can_control` / `can_consolidate` / `accepts_minority_investment` 重复表达 |
| `consolidation_path_summary` | 0% | 无 | 散文，内容归交易属性画像栏 |
| `earnout_dependency_status` | 0% | 无 | 无对手方枚举 |

四列均不出现在 `recommendation_flow.py` / `search_docs.py` / `recommendation.py` —— 删除不触碰打分与召回。

## 四、提示词（设置页发布，不发版）

`seller_target_research_mapper` **不用改** —— 它的字段目录与栏目目录都从注册表派生（`_mapping_context`），自动跟随。

### 4.1 `seller_target_parser` → 下一版

删掉正文里对这三个字段的全部说明：`management_team_summary`、`transfer_flexibility_type`、`consolidation_path_summary`。
它们的列已经不存在，模型再产出就会被 `SELLER_TARGET_FIELD_WHITELIST` 丢弃并记 `unsupported_field`。

`listing_market_region` 的取值说明改为：

````
- listing_market_region 只能取 sse / szse / bse / hkex / nyse / nasdaq /
  other / unknown 之一，分别对应上交所、深交所、北交所、港交所、纽交所、
  纳斯达克、其他交易所、未知。它是「在哪个交易所上市」，不是「境内还是境外」。
  股票代码后缀能直接判定：.SH → sse，.SZ → szse，.BJ → bse，.HK → hkex。
  未上市的标的省略该字段。
````

### 4.2 `seller_target_update_parser` → 下一版

  市场地位与排名、技术与研发能力、专利与资质、关键产能与资产、
  核心团队、主要客户与合作关系。

## 五、验收

1. **迁移**：CI 的 `Fresh database from baseline` 通过（空库应用 baseline 后 `upgrade head`）
2. **约束**：`entity_profile_section_section_code_check` 不再含 `tech_team`；两侧
   `chk_*_listing_market_region` 为 8 值闭集
3. **数据**：生产上 `tech_team` 当前版本行数为 0；产业优势栏有内容的标的 ≈ 24 个
   （原 `tech_team` 的 24 个），原 `business_product` 的 26 段成为软删版本
4. **信息页**：分组从 5 变 4；「业务与产品」下的补充栏标题显示「产业优势」；
   上市地下拉是 8 个中文选项
5. **打分**：`recommendation_flow.py` 零改动（`git diff` 里不应出现这个文件）
6. **回归**：926 passed / 4 skipped。新增守卫已逐条反向验证（改坏 → 对应用例挂）：
   - 去掉 `tech_team` 别名 → `test_a_retired_section_code_lands_in_its_successor`
   - 股东过滤退回 `tech_team` → `test_profile_parser_removes_cross_layer_deal_and_team_noise`
   - 枚举守卫只读 baseline → `test_registry_enum_values_valid_for_both_entities` + 守卫自身的回归
   - 迁移去掉股票代码推导 → `test_migration_clears_values_that_cannot_be_upgraded`
   - 补充栏标题退回「其他」→ `test_supplement_block_is_titled_by_what_belongs_in_it`

   顺带修好了一个既有守卫的盲区：`test_registry_enum_values_valid_for_both_entities`
   原来只读 baseline，约束被后续迁移重建过的列一律比不上 ——
   现在按迁移编号扫到最后一次定义，并锚在 `check (` 上、列名前加词边界
   （否则 `status` 会匹配到 `listed_status` 的约束）。
