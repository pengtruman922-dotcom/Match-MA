# R4 验收测试用例与问题上报模板（0723）

> **适用版本**：生产 `/health` 的 `git_commit_sha` 应为 `2983382` 或其后的提交。
>
> **本轮验收目标**：验证 R4 的标的信息模型、手动编辑审计、关系动态、看板可读性、排他提示，以及旧解析路径的兼容性。
>
> **明确不测/不判失败**：推荐结果「已在推进 / 新候选」分区；从自由文本自动识别对手方建关系；一条录入同时如何扇出事实更新、实体跟进和关系事件。这三项仍待单独讨论。

## 1. 开始前：环境与测试数据

### 1.1 版本确认

1. 打开 `https://match-ma-production.up.railway.app/api/v1/health`。
2. 记录 `railway.git_commit_sha`、测试时间、登录账号。
3. 建议管理员和普通顾问各测一轮涉及权限的用例。

### 1.2 准备一组可重复使用的数据

不要直接改真实在推进的项目。建立或挑选下列对象，并在报告中记录名称/ID：

| 代号 | 建议内容 | 用途 |
|---|---|---|
| T | 测试标的，例如「R4测试标的-0723」 | 信息页、手动编辑、关系与排他 |
| A | 买家主体 A + 意向 A | 与 T 进入深入推进 |
| B | 买家主体 B + 意向 B | 验证推荐/排他提示 |
| C | 无关顾问账号（如有） | 验证不可见性 |

建议给 T 准备以下值，便于肉眼核对格式与保存：

- `所在省/市/区`：广东省 / 深圳市 / 南山区；
- 行业：一级「医药与健康」、二级使用行业字典中存在的词；
- 营收：`123456789`；资产负债率：`45.6`；
- 出售比例：`51`；上市状态：未上市；是否还卖：是；
- 各组「其他」栏各填一句不同内容。

```text
版本确认
  → 信息页显示与编辑（TC-01 ~ TC-06）
  → 解析兼容与行业回归（TC-07 ~ TC-09）
  → 关系创建/动态/看板（TC-10 ~ TC-15）
  → 排他与权限（TC-16 ~ TC-18）
  → 回归边界确认（TC-19）
  → 汇总报告
```

每条用例都记录：实际结果、截图/视频、相关对象名或 ID、浏览器 Network 中失败请求的 URL/状态码/响应体（注意打码 token）。

## 3. 测试用例表

### A. 标的信息页与手动编辑

| 编号 | 操作 | 预期结果 | 级别 |
|---|---|---|---|

| TC-06 | 编辑后观察字段下方来源信息及「更新记录」 | 显示「手动编辑」、编辑人、时间；更新记录的新旧值与页面一致。 | P1 |

## 5. 严重度口径

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 无替代路径，核心功能无法使用，或发生越权/敏感信息泄露/数据损坏 | 信息页整体打不开；排他提示泄露买家 A 名称；迁移后推荐报错 |
| P1 高 | 核心业务结果错误或审计缺失，有有限绕行方式 | 手动编辑无法保存；深入推进未提示；系统动态可被删除；行业写错到非标准字段 |
| P2 一般 | 结果正确但展示、交互或提示不符合约定 | 卡片角色标签不清晰；格式不一致；错误提示不够具体 |
| 观察 | 已确认暂缓的领域问题，或需要产品决策才可定义对错 | 一条录入是否同时改变报价事实和实体跟进 |
