TC-20（同一段录入是否同时影响标的事实、实体跟进与关系事件）仍处于产品待讨论状态。只记录实际观察到的行为和原始文本，不以“没有自动更新标的字段”作为本轮失败结论。除非发生已有数据被错误覆盖、权限泄露或数据损坏，否则标为“观察项”。

推荐结果是否分为“已在推进 / 新候选”也不属于本轮验收范围；不要将其单独报为缺陷。

公开信息调研依赖尚未配置的 Tavily key，不能完成端到端调研不报错；但与该配置无关的前端崩溃、接口 5xx 或字段写错仍须上报。

## 5. 如何判定和记录问题

每一个失败项先确认：刷新页面后是否仍然存在、换一次操作是否可复现、是否和部署版本/测试数据/权限前置条件有关。能做到时，在浏览器 Network 中记录失败请求的 URL、HTTP 状态码和脱敏响应。

### 严重度标准

| 级别 | 判定 |
|---|---|
| P0 阻断 | 核心流程无替代路径，或越权、泄露敏感信息、数据损坏。例如排他泄露对方身份、关系创建整体失败。 |
| P1 高 | 业务结果错误、字段无法保存、审计缺失、排他提示缺失、手工/系统事件的权限边界错误。 |
| P2 一般 | 结果正确但展示、交互、格式或错误提示不符合约定。例如看板角色标签不清晰。 |
| 观察 | 已明确暂缓，或需要产品决策才有唯一正确答案的事项。 |

不要把同一根因拆成多个重复 BUG。先在报告中描述现象，若能证明多个用例由同一请求/字段导致，再合并为一个 BUG 并列出关联 TC 编号。
