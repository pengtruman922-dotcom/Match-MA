# 推荐报告双节点与 Word 导出施工单（0803）

## 1. 定稿范围

- 报告拆为两个独立 AI 节点：
  - `recommendation_target_report_writer`：面向买家客户的推荐标的报告。
  - `recommendation_buyer_report_writer`：面向卖方客户的推荐买家报告，展示真实买家名称。
- 每份建议选择 3–5 个候选，后端硬上限 10 个；1–2 个允许生成，但页面提示建议数量。
- 不兼容旧报告类型。迁移清理全部历史报告、报告消息、报告任务、报告 Trace 和报告附件关联，关系上的报告来源引用置空。
- 正文以受限 Markdown 文本为单一事实源。网页预览和 Word 下载使用同一正文，不另存第二套内容。
- 报告用于外部客户快速初判，不是尽调报告、估值报告或投资意见。

## 2. 输出契约

报告以自然语言为主，不输出 JSON，不做逐字段机械抄录。结构只保留阅读所需的最低限度：

1. 一个报告标题和简短说明。
2. 每个候选一个二级标题，先用一至两段话归纳画像和匹配逻辑。
3. 每个候选最多一个匹配概览表；固定四列为“评估维度 / 客户关注重点 / 候选现有情况 / 初步判断”，按业务大类整合字段，不要求与指标注册表逐行对齐。
4. 用短段落或少量列表说明主要关注点、信息缺口和待确认事项。
5. 每个候选给出一段简要结论；报告末尾可再给一个整体跟进建议。

允许的 Markdown 仅包括 `# / ## / ###` 标题、普通段落、无序列表、`**粗体**`、引用块和简单表格。禁止 HTML、代码块、嵌套表格、表格单元格内列表以及超过四列的表格。

## 3. Prompt：推荐标的报告

### System Prompt

```text
你是 Match-MA 的客户报告撰写顾问。你的任务是为买家客户撰写“推荐标的报告”，帮助客户在几分钟内判断每个候选标的是否值得继续了解和跟进。

这是一份浅层推荐报告，不是尽职调查、估值报告或投资意见。只能使用输入上下文中的事实、画像长文本、推荐规则证据和深评内容，绝不补造数字、主体身份、交易状态、风险或结论。必须清楚区分：已有事实、基于现有信息的初步判断、仍待确认的信息。

写作要求：
1. 面向外部客户，使用自然、克制、清楚的中文，不出现内部操作说明。
2. 以文本叙述为主，综合同一业务大类下的结构化字段、长文本和深评内容；不要按数据库字段逐项抄录，也不要把所有内容强塞进表格。
3. 每个候选先用一至两段概括业务、经营、交易属性及其与买家需求的匹配情况。只有确实有助于快速比较时，使用一个四列表格，列名固定为：评估维度、客户关注重点、候选现有情况、初步判断。表格行按大的业务分类整合，不要求与现有指标逐行对应。
4. 对风险、信息缺口和不确定信息使用“需确认”“现有资料未说明”等准确表达；不得把缺少信息说成不符合条件。
5. 每个候选末尾给出简短结论，说明是否值得继续了解以及下一步优先确认什么；报告末尾可给整体跟进建议。
6. 不展示数字评分、A/B/C 档、内部推荐等级、算法、规则引擎、节点、Prompt、Trace、系统 ID、负责人、联系人或联系方式。
7. 不写冗长方法论、宏观行业研究、估值推演、交易结构设计或尽调清单。

只输出中文 Markdown 正文，不输出 JSON，不加代码围栏。只允许标题、段落、无序列表、粗体、引用块和最多四列的简单表格。表格单元格内不得放列表或嵌套表格。
```

### User Prompt

```text
请根据以下报告上下文撰写推荐标的报告。

请优先理解买家需求与当前生效条件，再综合每个候选标的的完整字段、各分类“其他”长文本、匹配证据和深评内容。对同义、重复或跨字段的信息进行归纳，不要逐字段复述。若上下文中的旧摘要与更完整的现有画像存在表述差异，以具体事实为准，并把无法判断的部分写成待确认事项。

报告上下文：
{{ report_context_json }}
```

## 4. Prompt：推荐买家报告

## 5. 上线配置

Prompt 不通过迁移写种子。代码部署并完成 `014` 迁移后，在设置页“AI 节点”中分别为两个新节点绑定模型，然后在“Prompt 版本管理”按上述内容各发布一个启用版本。两节点均使用 `output_mode=text`、无 JSON response format；建议温度 `0.3`、超时 `180s`。

配置完成后检查健康指标：旧 `recommendation_report_writer` 应处于退役且不再显示；两个新节点均应配置模型和启用 Prompt。分别用一个正向、一个反向会话生成报告，确认 Trace 的 `node_name` 与方向一致。

## 6. 验收

- 正向只生成 `buyer_facing_target_report`，反向只生成 `seller_facing_buyer_report`；错配请求返回 400。
- 11 个候选时前端禁止提交，绕过前端调用 API 仍返回 400。
- 上下文包含指标字段、买家/标的“其他”长文本、买家方案和最近一轮完整深评内容。
- 推荐买家报告显示真实买家名称，不出现内部评分、档位或算法信息。
- 网页能安全预览标题、段落、列表、引用和四列表格。
- Word 下载使用同一 Markdown，中文字体、标题层级、粗体、列表和表格可正常打开与分页。
