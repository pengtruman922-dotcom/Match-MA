# Match-MA 推荐对话优化方案（0719）

目标：用户能够准确、流畅、可灵活变动地通过对话搜索推荐标的或买家，并生成推荐报告。

## 1. 现状问题（已核实）

1. 对话是装饰性的：`user_message` 只存档，不影响候选生成，也不进深评 prompt；系统回复是写死文案。
2. 条件无法在推荐页调整，"查看条件"抽屉只读；改条件必须回头改买家意向实体。
3. "生成推荐报告"按钮未绑定事件；后端报告链路（任务、LLM 撰写、列表/详情）完整但无 UI。
4. 会话不可回访：后端有最近会话/恢复/运行中会话全套接口，前端未消费；刷新即丢现场。
5. 细节：对象下拉仅 50 条不可搜索；候选卡片无详情链接；深评轮询超时后无重试入口。

## 2. 页面设计：单一对话流（已确认）

推荐卡片内嵌在对话流中，条件压缩为顶部 chips 行，整页一条时间线：

- 顶栏：模式切换、对象搜索选择、最近推荐、已选抽屉、生成报告。
- 条件 chips：灰色=来自意向基础条件，蓝色=对话补充（可单独 ✕，阶段二）；[恢复默认]。
- 对话流：系统消息 / 用户消息 / 候选卡片组消息。每轮筛选生成一个卡片组
  （默认展开前 5 项 + 展开全部）；**只有最新一轮卡片组可操作**，历史轮次折叠为
  一行摘要（"第N轮: … 已被取代，点击展开回看"）。
- 深评异步：卡片组先显示规则初排 + "深评中"角标，完成后**原地**重排并补
  A/B/C 评级与理由，不新发消息。
- 已选抽屉：列出已加入项（可移除）；报告生成后作为系统消息出现在对话流。
- 会话恢复 = 回放整条时间线（`/recommendations?session={id}` + bundle 接口）。

## 3. 对话流程：LLM 提取 + 代码路由（已确认）

一次 LLM 调用只做"提取+分类"，路由由代码根据提取结果推导（不让 LLM 拍板）：

| 提取结果 | 路由 | 执行 | 延迟 |
| --- | --- | --- | --- |
| 有结构化条件操作 | ① 全量重筛 | 合并条件→SQL重筛→深评 | 秒出+~1分 |
| 只有语义偏好 | ② 仅重新深评 | 候选不变→深评重评级 | ~1分 |
| 只有展示操作 | ③ 本地过滤 | 过滤当前卡片组 | 即时 |
| 只有提问 | ④ 上下文问答 | LLM 带当前候选做 QA | 几秒 |
| 混合 | ① 优先，答复附后 | | |

关键依据：当前 top-20 是从 ~200 候选池截断的，结构化收窄若只在展示集里过滤会
漏掉池内其余符合项，**必须回库重筛**；纯语义偏好候选集不变，只需对现有候选重
新深评。④ 为新增能力，可裁剪（第一版可降级为固定回复）。

## 4. 阶段一（先行）：接通现有能力

1. 推荐页重构为对话流布局（上节），前端 features/recommend/ 模块化。
2. 报告生成：确认弹窗 → `POST /sessions/{id}/reports/jobs` → 轮询 → Markdown
   预览 + 会话历史报告；导出 Word/PDF 暂不做（字段已预留）。
3. 最近推荐入口（`GET /recommendations/page`）+ 会话恢复（bundle）。
4. 细节：对象选择器搜索（suggestions 接口）、候选卡片详情链接、深评超时提供
   "重新深评"（rerank-jobs 接口现成）、对话消息读写后端持久化。
5. 后端小改动：`POST /recommendations/candidates` 增加 `session_id` 参数支持
   会话内多轮（续用会话：写入用户消息 + 新一轮候选消息 + 深评任务带轮次
   idempotency 后缀）；条件 chips 阶段一为只读展示。

## 5. 阶段二：对话驱动推荐

1. 迁移 041：`recommendation_session.condition_overrides_json`（结构：
   structured ops / semantic_preferences / cleared_base_fields）；新节点
   `recommendation_query_parser`（推荐条件解析）首次装配 seed（后续版本走设置页）。
2. 条件解析节点（中文提示词）：输入=用户消息+当前生效条件+行业字典
   （`{{ industry_l1_list }}`）；输出=condition_ops（set/relax/remove/exclude，
   字段白名单：行业/地区/净利/营收/PE/市值/估值/并表/控股/排除词）、
   semantic_preferences、display_ops、question、reply_summary；解析不出的进
   semantic_preferences，不臆造。
3. 候选生成合并覆盖：意向基础条件 + 会话覆盖 → SQL 与打分；语义偏好+用户原话
   注入深评 query。
4. candidates 接口响应增加 applied_conditions / parsed_ops / system_reply
   （模板化回复，不上 LLM）。
5. 条件 chips 变可交互：对话补充可单条 ✕、基础条件可会话内临时禁用、恢复默认；
   面板操作与打字殊途同归（操作也生成系统确认消息）。
6. 覆盖不自动写回意向；提供"把当前条件沉淀到意向"按钮走既有更新流程。

## 6. AI 设置与提示词优化

现状：8 个 LLM 节点提示词全英文；行业字典仅为 `{{ industry_l1_list }}` 占位符，
编辑时不可见；编辑器为裸文本框（无变量说明/渲染预览/few-shot 陷阱提示）。

1. 提示词中文化：逐节点发中文新版本（设置页操作，不发版）；输出 schema 与字段
   名严格不动；发布前用节点测试跑样例对比，异常一键回滚。
2. 编辑器升级：变量面板（variables_json 展示+点击插入）、行业字典当前内容实时
   预览、`POST /model-config/prompts/render-preview` 渲染预览接口、few-shot
   死存储界面警告。

## 7. 批次划分

1. 第1批：阶段一整体（页面重构+报告+会话+细节+后端 session_id 续用）。
2. 第2批：Prompt 编辑器升级。
3. 第3批：提示词中文化（设置页操作，可与第2批并行）。
4. 第4批：阶段二后端（迁移 041、条件解析节点、合并逻辑、路由）。
5. 第5批：阶段二前端（chips 交互、语义偏好注入展示、沉淀到意向）。

每批独立提交上线，CI + 生产 `/health` hash 验证。
