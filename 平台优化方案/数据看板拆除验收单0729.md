## 1. 行业字典（`行业字典0729.csv`）

### 1.1 做了什么

以「清洗后卖家表0116.xlsx」144 行、55 个自由文本行业值为输入，对照生产字典
（16 个一级 / 157 个二级 / 26 个已有别名）做补缺、填空、别名映射。

| 项 | 数量 |
|---|---|
| 文件总行数 | 183（16 个 L1 行 + 167 个 L2 行） |
| 一级行业 | 16（不变） |
| 二级行业 | 167（157 沿用 + **10 新增**） |
| 新增别名 | **40**（与已有 26 个零冲突） |

**新增二级行业 10 个**，分两类，第二类可以整行删掉不影响其它内容：

| L1 | 新增 L2 | 依据 |
|---|---|---|
| 环保与公用事业 | 公共设施管理 | Excel 有据（公共设施管理业） |
| 制造与工业 | 电气机械 | Excel 有据（电气机械和器材制造业） |
| 制造与工业 | 印刷包装 | Excel 有据（印刷和记录媒介复制业） |
| 军工 | 军工电子 / 兵器装备 / 航空航天装备 / 船舶与海洋工程 | **无据补位**，仅为填平 0 个 L2 的空 L1 |
| 商务与专业服务 | 法律服务 / 财税与审计 / 知识产权服务 | **无据补位**，该 L1 原本只有 4 个 L2 |

「其他」保持 0 个 L2 —— 它是兜底桶，加 L2 没有意义。

### 1.2 已验证

- 离线校验：别名不与任何规范词重名、不与已有别名争主、二级行业不改挂父级、新词不撞名 —— **0 错**
- **生产 dry-run**（`POST /data-dictionaries/industry/import?dry_run=true`，不写库）：
  `total_rows 183 / ready_rows 183 / error_rows 0`

### 1.3 必须知道的三件事

**(1) 导入是纯 upsert，不会删除任何东西。** 文件里没列的词原样保留，所以这次上传是安全的、可重复的。

**(2) 6 个 Excel 写法做不成别名 —— 导入解析器会把它们切碎。**
`_split_aliases` 会把 `，`、`、`、`;`、`；` 当分隔符，含这些字符的别名会被拆成两段。受影响的：

| Excel 原值 | 应指向 |
|---|---|
| 电子元件（半导体、集成电路等） | 电子元件 |
| 化工（纺织、橡胶塑料等） | 化工 |
| 食品（副食、休闲食品） | 休闲食品 |
| 食品（主食与大宗副食品，如粮油糖肉蛋等） | 粮油食品 |
| 酒、饮料和精制茶制造业 | 酒水饮料 |
| 文化传媒（体育、演艺院线、广告与内容制作） | 体育演艺与内容制作 |

它们**已从 CSV 中剔除**。走设置页「编辑词条」逐个手动添加即可（那条路径不做切分，能收下）。

**(3) 字典内部的同义词重复，本次没有解决，也无法靠导入解决。**
字典里 `半导体 / 半导体与集成电路 / 集成电路 / 芯片` 是四个独立 L2，
`有色金属 / 有色金属及矿业 / 采掘与矿业 / 采矿业 / 矿业` 是五个，另有
`生物制药 / 生物医药 / 制药 / 药品生产`、`食品 / 食品制造 / 食品加工`、
`建材 / 建材家居 / 家居建材`、`文化旅游 / 文旅 / 旅游` 等。

为什么导入解决不了：
- 把重复词转成别名 → 被 `_validate_import_rows` 拒绝（「别名已被标准行业占用」，且该检查**不看 active**，先停用也没用）
- 只停用重复词 → **反而更糟**：`resolve_l1` 带 `active = true` 过滤，停用后该词连 L1 都解析不出来，会掉进「其他」

要真正合并需要三件事，构成下一个独立工单：
1. 代码：`normalize_l2_values` 跟随 `canonical_term_id` 解析别名（现在别名只解析到 L1，L2 会被丢弃并记 `industry_l2_unmapped`）
2. 迁移：把重复 L2 行翻成 `level='alias'` 并回填 `canonical_term_id`
3. 回填：改写存量 `industry_pairs_json` 里的旧 L2 值（字典改了不会动已存的 JSON）

**这件事是数据看板「二级赛道」图不失真的前提**；本轮看板只做一级行业分布，暂不阻塞。

### 1.4 上传步骤

1. 设置页 → 数据字典 → 行业字典 → 导入，选 `平台优化方案/行业字典0729.csv`
2. 先看 dry-run 预览，确认 183/183 ready
3. 确认后正式导入
4. 导入完到「行业字典」列表抽查：`控股平台` 应带 2 个别名、`生态环保` 应带 3 个、`军工` 下应出现 4 个 L2

### 1.5 上传断连复核与修复

- `Failed to fetch` 发生在浏览器收到 HTTP 响应之前；结合间歇性 `SSL: UNEXPECTED_EOF_WHILE_READING`、健康检查和同文件生产 dry-run 成功，根因位于客户端到 Railway 的 TLS/传输链路，不是 CSV、CORS 或导入业务校验。
- 原正式导入逐项执行 select + update/insert：本文件约 781 次 `Session.execute`（校验 1 + canonical 700 + alias 80），长请求会放大链路断连窗口。
- `data_dictionaries.py` 已改为单事务内按 L1/L2/alias 批量写入：现状读取 1 次，最多 6 个写批次；正式导入另用事务级表锁保证校验与写入之间没有并发同名词。失败仍整体回滚，不采用会产生半导入状态的分块提交。
- 前端网络错误改为先显示原始 reason，再提示重试；Railway 部署检查降级为“持续失败”后的排查项。

Dashboard 空壳只声明两块内容：**标的省级分布地图** 与 **一级行业分布**。按你的决定，
顶部数字条不做；页面不出现任何标的与买家名称。

### 2.2 残值并入账号管理

`USER_LIST_SQL` 新增 `latest_activity_at` 列，`UserOut` 增加同名字段，`Users.tsx` 加「最近活跃」列。
负责标的/买家/意向三个计数**本来就在** `USER_LIST_SQL` 里，页面上也早有这三列，无需搬运。

**口径修正（这是本节的重点）**：旧算法把
`max(seller_target.updated_at)` / `buyer_party` / `buyer_intent` 算进活跃度，
而 `field_writer.py:216` 每次写字段都 `updated_at = now()` —— AI 解析和调研回填会把负责人刷成
「刚活跃」。新口径只取**人主动做的事**四张表：

```
business_update.created_by/created_at
relation_event.created_by/created_at   (deleted_at is null——撤回的动态不算)
action_application_log.applied_by/applied_at
recommendation_message.created_by/created_at
```

从未动过手的账号返回 `null`，前端显示「—」，不是一个假时间。

### 2.3 撮合看板「指定负责人」

| 文件 | 改动 |
|---|---|
| `backend/app/api/routes/utils.py` | 新增 `relation_owner_sql(alias)`，谓词与 `relation_visible_sql` 同形但用独立参数 `:owner_user_id` |
| `backend/app/api/routes/relations.py` | `/relations/board` 新增 `owner: UUID \| None` 参数 |
| `frontend/src/features/board/BoardFilters.tsx` | 新增负责人下拉，**仅管理员渲染**（`/users/options` 是 admin-only） |
| `frontend/src/features/board/useBoardData.ts` | `owner` 进依赖数组，变更触发重新取数 |
| `frontend/src/pages/Board.tsx` | `owner` 进 URL 参数；空态文案区分「该负责人名下没有关系」 |

两个刻意的设计决定：

1. **独立参数名**。`:owner_user_id` 与权限地板的 `:scope_user_id` 分开——共用一个名字会让后写的
   值覆盖前一个，把权限地板悄悄变成视图筛选。有专门测试盯这点。
2. **裸 `None` 默认值而不是 `Query(default=None)`**。后者的 Python 默认值是 `Query` 实例本身，
   直接调用该函数（测试、内部复用）时 `owner is not None` 会成立，于是把一个 `FieldInfo`
   当 UUID 绑进 SQL。有专门测试盯这点。
3. **owner 与 ownership 是 AND，不放宽权限地板**。非管理员即使构造 URL 挑别人，也只得到交集
   （通常为空）。筛选器不能成为越权读取的入口。
