## 本包必须完成的结果

### 1. 归一主 Agent 最终输出

按总施工单 4C.1 实现并校验：

- `understanding`；
- `recommended_ids`：深评 ranked 中的 3–6 家，候选不足 3 家时按实有数量；
- `runner_up_ids`：ranked 中未入重点名单的最多 5 家；
- `selection_notes`；
- `follow_up_suggestions`：2–4 条可直接发送的短句。

Agent 有选择权，但没有事实写入权。代码必须保证：

- 正常深评时重点/备选 ID 只能来自 `ranked`，不能来自 `dropped` 或池外；
- 编造 ID、重复 ID、超上限内容被丢弃/截断并留 trace；
- 名称、画像 facts 和数字只从代码持有的数据填充，不采信模型输出；
- 深评降级时允许 `agent_fallback`，但必须显式标明来源，不伪装成 deep_eval；
- 不由代码固定取深评前 5，也不把所有深评候选都写成最终重点名单。

### 2. answer brief v2

按总施工单 4C.2 建立唯一 Writer/规则兜底/前端共享素材包，包含：

- 当前需求摘要与 parser/deep-eval/selection 状态；
- `candidate_pool_count` 与是否截到 40；
- `screening_runs`；
- 重点与备选的数据库事实、定性判定、理由、风险、信息缺口、筛选来源和放宽状态；
- `follow_up_suggestions`。

删除新 brief 中错误的旧 `total_eligible` 口径。多组、多次查询时最后一次 `matched` 不是“全库符合数”，
Writer 和兜底都不得再写“总共符合 N 家”。可以如实说“本轮汇总了 N 家去重候选”。

### 3. Writer Prompt v0.2.0 与规则兜底

复用 `recommendation_answer_writer_to_target`，不新建节点。Writer 只读 brief v2，并严格做到：

- 区分完整条件命中与放宽后补充；required 放宽候选写明需核实/供参考；
- 数字只引用 facts；定性理由来自深评字段；不展示等级或分数；
- 不输出 ID、URL 或 Markdown 链接，名称链接仍由代码安全回填；
- 不把追问建议改写进正文末尾；
- 不泄露与标的深入推进的其他买家身份；
- 候选少时不为满足字数灌水。

`fallback_answer_markdown` 与 Writer 使用同一口径：使用 `candidate_pool_count`，展示理由/风险/缺口和放宽项，
不把追问写进正文；无重点候选时输出诚实空结果说明。

Prompt 走 API，不写 seed 迁移；发布脚本要支持变量检查、render-preview 和同版本冲突失败。
未经用户明确许可，不要 apply 生产 Prompt。

### 4. 收口已有追问芯片

前端已有 `AgentTurnView` 芯片和点击即发送能力，**不要重做第二套组件**。只做契约适配与必要的最小改动：

- 正文完成后显示 2–4 条短句，去重、不显示空项；无可靠建议允许少于 2 条或为空；
- 点击芯片直接成为下一轮用户消息；随后由最近 5 轮问答驱动需求解析；
- 优先支持细看某家、放宽/恢复条件、收窄行业地区、再看下一批；
- 可以引用真实名称，不输出 ID、链接，不承诺列出超过预算的全集；
- 中止、失败、澄清态不显示；
- 恢复历史会话时从已落库 brief 恢复相同芯片。
