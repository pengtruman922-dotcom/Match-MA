## 五条最容易踩的

1. **不要复用标的调研的 handler。** `entity_type != "seller_target"` 直接抛错，
   而且共用栏目目录有实测代价 —— 历史上 agent 照着买卖合成的目录填，
   映射节点原样转发，最后被丢掉，**实测浪费 14 次**。按实体建，别图省事。

2. **解析节点走 `llm` 队列，调研节点走 `research` 队列。**
   research 队列是多副本、stale 1800s，为十分钟级长任务设计的。
   把秒级解析放进去，它会排在长任务后面。

3. **materials 里的指令性文字要当噪音忽略。**
   生产里买家材料的抬头经常是「解析要求：……**不要生成或修改买家主体资料**」，
   而你这个节点的任务恰恰是修改买家主体资料。提示词里要显式声明忽略。

4. **归一化节点不裁决真冲突。** 解析说「私企」、调研说「国企」，
   两边同期且都有证据时，**落成待复核提案，不要让模型选一个**。
   模型没有额外信息，让它选就是让它猜。

5. **Prompt 不写 seed 迁移。** 三个新节点的 Prompt 通过设置页 /
   `/model-config/prompts` API 创建，迁移只管 schema。这是 `AGENTS.md` 的硬规则。
