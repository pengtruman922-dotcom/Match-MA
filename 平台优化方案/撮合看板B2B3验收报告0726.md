## 3. 缺陷明细

### BUG-01：时间线抽屉标题与关闭按钮被顶部导航遮挡

- 关联用例：3.9-3；同时影响标的侧与买家意向侧
- 严重度：P2
- 环境与部署 hash：本地 B2/B3 dev server + 生产 API `2aef084`
- 测试对象：标的 `13466e54-3aae-4a3c-9ec9-ad1a2008577d`，关系 `3adb0d27-101e-4b65-8410-5b232022f9f4`

**复现步骤**

1. 本地登录后打开 `/board`。
2. 点任一标的卡进入 `?tab=progress&relation=...`。
3. 观察自动展开的右侧时间线抽屉顶部。
4. 尝试点击抽屉右上角 X。

**预期结果**

抽屉标题、对手方名称和 X 关闭按钮完整可见，X 可直接点击。

**实际结果**

全局 header 覆盖抽屉顶部约 97px，抽屉标题和 X 不可见、不可点击；点击左侧灰色遮罩仍可关闭，故存在替代路径。

**可复现性与影响范围**

- 可复现性：稳定复现，标的侧、买家意向侧均复现。
- 影响范围：所有时间线抽屉，不只 B3 深链接。

**证据**

- 页面 URL：`http://localhost:5190/targets/13466e54-3aae-4a3c-9ec9-ad1a2008577d?tab=progress&relation=3adb0d27-101e-4b65-8410-5b232022f9f4`
- 截图：[时间线抽屉遮挡证据](./验收证据/撮合看板B2B3-时间线抽屉遮挡0726.png)
- DOM 测量：header `top=0,bottom=97.4,z-index=50`；关闭按钮 `top=40,bottom=64`；drawer `z-index=40`。
- 代码证据：`Layout.tsx:43` 为 `z-50`；`RelationTimelineDrawer.tsx:65` 为 `z-40`，关闭按钮在 `:80`。

**建议修复**

统一 overlay 层级规范：时间线 drawer 高于全局 header（例如 drawer/backdrop `z-[60]`），并给关闭按钮增加 `aria-label="关闭时间线"`。修复后在 1280×720 和 900×720 两个视口复测。

### BUG-02：深链接抽屉关闭后切换 tab 会自行重开

- 关联用例：3.9-8
- 严重度：P2
- 环境与部署 hash：本地 B2/B3 dev server + 生产 API `2aef084`
- 测试对象：同 BUG-01

**复现步骤**

1. 用 `?tab=progress&relation=3adb0d27-...` 打开测试标的，确认抽屉已展开。
2. 点灰色遮罩关闭抽屉，确认时间线标题消失。
3. 点“标的信息”，再点“推进”。

**预期结果**

未刷新、relation 参数未变化时，用户主动关闭的抽屉不应自行重开。

**实际结果**

关闭后时间线数量为 0；切“标的信息→推进”后时间线数量重新变为 1，同一 relation 自动重开。

**可复现性与影响范围**

- 可复现性：稳定复现。
- 影响范围：标的侧和买家意向侧均使用条件挂载的 `ProgressPanel`，两侧同理。

**证据**

- 浏览器实测：`afterClose=0`，`afterInfoThenProgress=1`，URL 始终保留原 `relation`。
- 代码证据：`ProgressPanel.tsx:35` 每次挂载用 `initialOpenId` 初始化；`TargetDetail.tsx:228` 与 `BuyerIntentWorkspace.tsx:89` 仅在 progress tab 条件挂载组件。

**建议修复**

关闭抽屉时从 URL 删除 `relation`，但保留 `tab=progress`；或在详情页上层维护“本次 relation 已被用户关闭”的状态并跨 tab 保存。推荐清 URL，语义更直观，也同时解决已知的“关闭后刷新重开”体验问题；刷新可复现性应由复制原始深链接而不是关闭后的地址承担。

### BUG-03：折叠摞“最近”时间取了最深状态成员，而非最近活动成员

- 关联用例：3.6-5（排序本身正确，但摞头摘要错误）
- 严重度：P2
- 环境与部署 hash：本地 B2/B3 dev server + 生产 API `2aef084`
- 测试对象：意向 `0706a6f4-04a2-4c8d-aca8-e0056cb1241d`，初步接触 `×10` 摞

**复现步骤**

1. 打开 `/board?view=intent`。
2. 找到“黄河产业-并购需求（2026-07） ×10”的收起摞。
3. 读取摞头的“最近”摘要和时间。
4. 用 board API 对比组内 `last_activity_at` 最大值。

**预期结果**

摞头“最近”对应组内 `last_activity_at` 最大的关系。

**实际结果**

摞头显示“最近 黄河产业 / 3天前”；组内实际最新关系是 `9bf889e5-0c7e-42b1-9ced-235fa0ff4da7`（已推荐，`2026-07-24 06:36:34+00`），而 UI 取的是更深但更旧的 `4eb924a8-bdf6-4df5-8b75-b3134a3c0a42`（沟通中，`2026-07-23 06:38:33+00`）。

**可复现性与影响范围**

- 可复现性：稳定复现。
- 影响范围：任何“最深状态成员不是最近活动成员”的折叠摞；目标视角和意向视角均可能发生。

**证据**

- 截图：[折叠摞最近活动错误](./验收证据/撮合看板B2B3-折叠摞最近活动错误0726.png)
- API 对比：上列两个 relation 的状态与时间。
- 代码证据：`boardBuckets.ts:138` 先按深度排序 `relations`；`RelationGroupCard.tsx:15` 又把 `relations[0]` 当 `latest`，`:48` 显示其 buyer/time。

**建议修复**

在 `BoardGroup` 中明确保存 `latestRelation`（按 `last_activity_at` 选），代表状态继续使用 `deepestStatus`，不要让一个数组顺序承担两种语义。意向视角的“最近买家”恒等于当前买家，建议对称显示“最近标的”。

## 4. 观察项与未测项

### 4.1 未测项

1. 普通顾问权限地板：只有管理员凭证。三态计数和 sole 谓词已在管理员下得到判别并逐条核对，但不能替代普通顾问在 `OWNER_SCOPE_ENFORCED` 下的可见性回归。
2. 同一已挂载详情组件内只变化 `relation` query：现有 UI 没有这种入口，真机无法触发；建议用 React Router 组件测试覆盖 `initialOpenId` 变化 effect。
3. `ProgressPanel` 100 条截断告警：单实体最多 13 条；未制造 100 条生产关系。
4. 看板 2000 条截断告警：生产仅 44 条；未触发。
5. “显示更多”：当前任一块均不足 40 组；未触发。

### 4.2 观察与优化建议

1. **搜索口径变窄可暂时接受，但应收集使用反馈。** 当前 placeholder 已明确只搜标的/买家/意向名称，且客户端筛选能准确显示“隐藏 N”。代价是动态摘要和状态原因不再可搜。若用户确有该习惯，建议后端改成返回 `{items, total, filtered_total}` 或增加轻量搜索索引/匹配 ID 端点，而不是把事件长文本重新塞回 9 字段 board 卡片。
2. **`BOARD_FETCH_LIMIT=2000`、每块 40 条、列高 `calc(100vh-19rem)` 在当前 44 条数据下工作正常，但缺少压力证据。** 建议后续引入可注入的前端 fixture，在 2000 条、>40 组、100 条单实体三个边界做组件/浏览器测试。
3. **57 项算法断言应收编进 Vitest。** 本轮组件、hook、URL 与 B3 仍无自动化回归；本次发现的 BUG-02/03 都不会被现有纯函数 scratchpad 自动抓到。
