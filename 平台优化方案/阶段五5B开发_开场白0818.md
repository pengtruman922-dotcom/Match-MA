## 五个容易做错的地方，先打预防针

1. **新旧条件解析函数名高度相似。** `parse_recommendation_message` vs
   `parse_recommendation_intent`、`fallback_parse_result` vs `fallback_intent_parse_result`、
   `normalize_parse_result` vs `normalize_intent_parse_result` —— 前者是要删的旧的，
   后者是新链路的核心。**按完整名字匹配，不要用前缀或模糊搜索。**
   `recommendation_conditions.py` 的**上半部分一个字都不能碰**。
2. **删报告会再动一次黄点判据。** `_recommendation_session_is_processing` 现在是
   `agent_status` OR `report_status` 两支（5A 删掉了 rerank 那支）。
   删报告后**只剩 `agent_status` 一个来源**。这是 4D 花一整包修对的东西，
   `test_recommendation_page_status.py` 的 fixture 要从 `report_status` 改挂到
   `agent_status`，**断言不要动**。同时会空掉的还有：
   `_filter_recommendation_session_summaries` 的 failed/generated/idle 三个分支、
   `_recommendation_page_overview` 的计数、`_recommendation_session_polling_hint` 的
   `watched_jobs` 与 `reason`。
3. **候选渲染簇不随 `/candidates` 走，但随 B 类走。** 它们读的是历史候选消息
   （bundle / page-state 渲染），不是生成候选。决策一已拍板删，
   所以**整簇一起删**——混着来会留下一半能编译但永远没数据的代码。
4. **`test_node_registry.py` 的字面量棘轮是精确相等断言。** 删掉含节点名字面量的代码后
   必须同步 `KNOWN_LITERAL_SITES`（**少了也会挂**，不只是多了）；
   删 `NodeSpec` 还会让三条 `parametrize("spec", NODES)` 用例自然减少，属正常。
5. **删代码会顺手废掉一些测试的「唯一覆盖」。** 5A 踩过：删掉某个节点后，
   `upsert_catalog_node` 里 `spec is None or spec.lifecycle != "active"` 的后半句失去覆盖。
   正确做法是**把用例改指向仍存在的同类对象**，而不是把用例删掉——删掉会静默丢覆盖。

## 验收标准和以往不同，请注意

这是删除类改动，**「全绿」不是合格标准**——把测试连同代码一起注释掉也能全绿。

| 指标 | 期望 |
|---|---|
| 后端 `python -m pytest -q` | **通过数下降、失败数为 0**（基线：5A 后是 1142 passed / 36 skipped） |
| 前端 | `npm run typecheck && npm run build && npm run lint` 全过 |
| 行为 | 一轮真实推荐的四段消息、黄点绿点、追问芯片、链接回填**完全不变** |
| 新增代码行 | **接近 0** |

收工时必须报告：**删了哪些测试、为什么它们没有保留价值、通过数从多少变到多少。**
如果某一批删除产生了大量新增代码，说明不是在删而是在借拆除之名重构——停下来说明理由。

⚠️ **测试要跟着代码一起删，不要试图改造。** `_score_target_against_intent` 有 30 处
测试引用、`_candidate_targets_for_intent` 9 处、`derive_route` 8 处。它们测的是**打分语义**
——新链路里根本没有分数这个东西，硬改成「测新链路」只会产出一批名不副实、断言空洞的测试。
（与之相对，第 5 条说的「唯一覆盖」是另一回事：那是仍然存在的代码路径，要保住。）

本机是 Python 3.14、无后端 venv，直接 `python -m pytest` 即可（`py -3.11` 不存在）。
