# Match-MA 代码地图

> **定位**：本文件回答「代码在哪、该改哪个文件」。
> 「系统是什么、应该长什么样」看 `docs/系统总纲.md`（图纸，权威）。
> 「不能违反的硬规则」看 `AGENTS.md`（部署拓扑、Git、测试、迁移、同步约束）。
> 「接下来改什么」看 `平台优化方案/*.md`（施工单）。
>
> 本文件不带日期后缀、不另起新文件：就地修改，git 是版本历史。
> 最后更新：2026-08-01

技术栈：FastAPI + PostgreSQL（raw SQL，无 ORM 映射）+ React/TS + Vite + Tailwind。

---

## 1. 顶层结构

```
backend/          FastAPI 应用
frontend/         React + Vite 前端
database/         迁移 SQL（001_baseline.sql 是地板）
alembic/          Alembic 修订，执行 database/migrations 下的 SQL
tests/            pytest（跑在仓库根，不需要 venv）
scripts/          Railway 启动脚本、生产验证工具
deploy/           自建 Docker Compose 部署（只服务自建）
railway*.toml     Railway 服务配置（只服务 Railway）
docs/             图纸 + 本地图
平台优化方案/      施工单与历史方案
```

## 2. 后端分层

```
backend/app/
├── main.py              应用装配，挂 /api/v1
├── config.py            环境变量（新增变量要同步 .env.example 与 deploy/.env.example）
├── db.py                会话
├── api/routes/          HTTP 层：入参校验、鉴权、编排；24 个文件按业务域切
├── services/            业务逻辑；API 与后台任务共用的动作下沉到这里
├── jobs/
│   ├── queue.py         入队 / claim / 重试 / stale 回收
│   ├── worker.py 入口   backend/app/worker.py --queue <name>
│   └── handlers/        按任务域拆分的包，dispatch.py 按 job_type 路由
├── ai/                  LLM / rerank 客户端、prompt 渲染
└── registry/            结构化声明的单一真源（无 SQL、无传输代码）
```

### 分层铁律

**同一个业务动作，从 API 调和从后台任务调，必须是同一个函数。** 这是 services/ 存在的唯一理由。已下沉：`research_apply`、`profile_sections`、`business_update_flow`、`recommendation_flow`、`extracted_action_apply`。

`jobs/handlers/` 是包，`__init__.py` re-export 全部名字（**测试依赖这些 re-export，不要删**）。新增 handler 放对应域模块并在 `dispatch.py` 注册，跨域共享的 helper 放 `common.py`；**模块依赖必须无环**。

`registry/` 目前只有 `indicators.py`（结构化字段的唯一声明：字段名、写入权限、枚举、UI 元数据）。同构的声明性常量都应该放这里，而不是散在各处硬编码。

## 3. 后台任务与队列

**只有三个队列**：`llm` / `ocr` / `research`。两套部署都只起这三个 worker。
（`embedding` / `rerank` worker 已于 2026-07-31 下线，历史作业仍在库里。）

| job_type | 队列 | 说明 |
|---|---|---|
| `seller_target_parse` | llm | 标的新建解析 |
| `buyer_intent_parse` | llm | 买家需求解析 |
| `business_update_extract_actions` | llm | 统一业务更新抽取 |
| `relation_followup_draft_parse` | llm | 跟进整理 |
| `recommendation_deep_eval` / `recommendation_rerank` | llm | 深评（两个 job_type 共用一个 handler，rerank 是历史名） |
| `recommendation_report_generate` | llm | 推荐报告 |
| `seller_search_doc_rebuild` / `buyer_intent_search_doc_rebuild` | llm | 检索文档重建（纯 DB 文本拼接，不调模型） |
| `embedding_generate` | llm | 仅手动接口触发，向量链路已随推荐 v3 退役 |
| `model_node_test` | 按节点类型 | 设置页的节点业务测试 |
| `attachment_ocr_parse` / `attachment_ocr_poll` | ocr | 附件 OCR |
| `seller_target_research` / `seller_target_research_map` | research | AI 调研与结果规范化（单次 5~15 分钟） |

**新增或改名队列必须同步两套部署**，否则该队列的任务会在漏改的一侧静默堆积。详见 `AGENTS.md` 同步约束。

## 4. 前端结构

```
frontend/src/
├── pages/         路由级页面，一个业务页面一个文件
├── features/      按业务域拆的复合组件：board buyers dashboard recommend relations settings targets
├── components/    跨域复用组件（Layout / Modal / PaginationFooter / UploadArea …）
├── lib/api/       API 客户端（client.ts 统一 fetch 与错误处理，index.ts 按域导出）
├── lib/           auth、字段标签、格式化、状态映射
├── hooks/         useApi、useTableViewportHeight
└── types/api.ts   后端响应类型，手工维护，改接口时必须同步
```

页面变大就往 `features/<域>/` 拆，不要让 `pages/*.tsx` 无限膨胀。列表页的视口/分页遵循已统一的模式，见 `平台优化方案/标的列表横向滚动与分页改造施工单0730.md`。

## 5. 数据库

- `database/migrations/001_baseline.sql` 是地板（生产 schema 快照 + 种子，含现行 prompt 版本），对应唯一 alembic 修订 `20260722_0048`。**新迁移从 `002_` 起编号。**
- 迁移由 `backend/app/migration_sql.py` 的自制 splitter 解析后经 Alembic 执行。**新增迁移文件后必须跑 `tests/test_migration_sql.py`**（历史事故：注释里的分号切坏语句导致部署失败）。
- schema 依赖 `vector`（pgvector）与 `pg_trgm` 扩展，普通 postgres 镜像起不来。
- 后端全部用 raw SQL，没有 ORM 模型层 —— 改表结构不会有类型系统提醒你，靠测试和 code review。

表清单与死表判决见 `docs/系统总纲.md` §2、§6，不在此重复。

## 6. 测试

```bash
python -m pytest -q
```

本地无 venv，直接跑（本机 Python 3.14）。运行时行为对生产 API 验证：

```bash
python scripts/match_ma_api_tools.py health
```

必须从仓库根目录运行，token 读 `.match-ma-local-auth.json`。

**几个会挂 CI 的同步测试**，改相关代码时留意：

| 测试 | 守什么 |
|---|---|
| `test_action_type_sync.py` | action_type 三处声明（handler 常量 / DB check 约束 / apply 分支）一致 |
| `test_migration_sql.py` | 所有迁移文件能被 splitter 正确切分 |
| CI `Fresh database from baseline` | 空库应用 baseline 后与 schema 快照一致 |

## 7. 改 X 该看哪里

| 要做的事 | 入口 |
|---|---|
| 改某个 AI 节点的模型或提示词 | 设置页 → AI 设置（**不写迁移**，prompt 版本即时生效） |
| 新增 AI 节点 | `jobs/handlers/` 加 handler + `dispatch.py` 注册 + 设置页配模型与 Prompt |
| 改结构化字段的定义/枚举/写入权限 | `registry/indicators.py`（单一真源） |
| 新增 extracted_action 类型 | 三处同步，见 `AGENTS.md` |
| 改列表页筛选/分页 | `pages/<页面>.tsx` + `components/PaginationFooter.tsx` |
| 改推荐召回或深评 | `services/recommendation_flow.py` + `jobs/handlers/recommendation.py` |
| 改业务更新解析链路 | `services/business_update_flow.py` + `jobs/handlers/` |
| 加环境变量 | `config.py` + `.env.example` + `deploy/.env.example` 三处 |
| 加 worker 队列 | Railway 侧 toml + `scripts/railway_start.py`；自建侧 `deploy/docker-compose.yml` |
| 排查线上任务 | `/background-jobs` 任务中心，或 `scripts/match_ma_api_tools.py failures` |
