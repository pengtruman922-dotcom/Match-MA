# Match-MA Frontend UI Spec v0.1

日期：2026-05-28
状态：供 Bolt / 前端开发使用的页面与交互规范
关联文档：`prd_v0.1.md`

> 本文档重点描述页面结构、交互状态和验收要求。若当前前端实现与本文档冲突，应优先调整前端实现。

## 1. 全局布局

### 1.1 顶部导航

```text
+================================================================================================+
| Match-MA                                      [搜索标的/买家/意向...]      张三  [Debug Mode*]  |
+================================================================================================+
| 工作台 | 标的管理 | 买家管理 | 智能推荐 | 数据看板 | 设置                                      |
+================================================================================================+
```

说明：

- `Debug Mode` 仅管理员可见。
- 普通营销顾问不显示 Debug Mode 入口。
- 顶部搜索是高频能力，应在所有主页面保留。
- 数据看板和设置一期可占位。

## 2. 工作台首页

### 2.1 页面目标

工作台是任务板，不是展示板。

用户应能快速看到：

- 哪些自动更新需要复核。
- 哪些推荐需要跟进。
- 哪些解析失败或信息不足。
- 最近重要业务动态。

- “待确认”文案应尽量改为“待复核”或“已自动更新待复核”。
- 最近动态只展示信息流，不替代待办。

```text

|------------------------------------------------------------------------------------------------|
| 上海启元项目      医疗器械    浙江杭州  --        2500万   3.2亿    12.8  3   可推荐  推荐买家 |
|   摘要：医疗器械相关标的；并表/控股待确认；报价来自 05-28 业务更新，待复核        录入更新        |
|------------------------------------------------------------------------------------------------|

```

### 3.2 列设计

必须分列展示：

- 营收。
- 利润。
- 估值。
- PE。

不要合并为“关键字段”。

附件列：

- 显示附件数量。
- 点击可展开附件列表或跳转详情“附件与证据”。

状态列建议组合展示：

- 推荐状态：可推荐 / 暂不推荐。
- 信息状态：信息不足 / 需复核 / 解析中 / 调研中 / 异常。

### 3.3 行内操作

主操作只保留：

```text
推荐买家
录入更新
```

点击标的名称进入详情页。

## 4. 新建标的

### 4.1 表单结构

```text
+------------------------------------------------------+
| 新建标的                                             |
+------------------------------------------------------+
| 标的名称 *  [____________________________]            |
| 负责人      [当前用户 v]                              |
| 行业        [可选，留空由系统解析]                    |
| 地区        [可选，留空由系统解析]                    |
| 一句话描述  [____________________________]            |
| 附件        [上传 PDF/Word/PPT/Excel/图片，可选]      |
|                                                      |
| 疑似重复                                             |
|  - 上海启元项目 · 浙江杭州 · 医疗器械        [更新它] |
|  - 上海启元科技有限公司 · 浙江杭州           [更新它] |
|                                                      |
| [仍然新建] [取消]                                    |
+------------------------------------------------------+
```

### 4.2 交互要求

- 只要求标的名称必填。
- 去重检查必须快，不调用 LLM。
- 疑似重复只显示 Top 5。
- 名称过短时提示“名称过短，建议补充公司全称或地区”。
- 提交后立即入库并回到标的列表。
- 附件解析、OCR、联网调研异步执行。

### 5.2 Tab 规则

标的详情只设置：

```text
基本信息 | 附件与证据 | 关系/跟进 | 更新记录
```

不要单独设置“推荐记录”tab。

推荐记录进入“关系/跟进”。例如：

```text
2026年5月28日推给广工
```

应展示为关系/跟进中的一条事件：

```text
买家意向：广工相关收购意向
状态：已推荐
事件：2026-05-28 已推荐给广工
```

更新记录永远放最后。

### 5.3 基本信息分组

基本信息按 6 组：

```text
身份 | 行业业务 | 财务 | 估值交易 | 风险 | 信息缺口
```

字段值旁应尽量显示来源和更新时间。

`Debug Trace` 仅管理员开启 Debug Mode 后可见。

### 8.3 复核动作

- 标记已复核：不改变字段值，只更新复核状态。
- 编辑：打开字段编辑，并再次写入日志。
- 回退：恢复到本次自动应用前的值，并写入回退日志。
- 忽略：仅用于未应用或无法处理的动作。

- 模式切换。
- 当前对象选择器。
- 推荐企业数量。
- 已加入推荐列表数量。
- 生成推荐报告按钮。
- 查看条件按钮。

生成推荐报告按钮状态：

- 已加入数量为 0：禁用，但可见。
- 已加入数量大于 0：高亮可点击。

### 9.3 条件抽屉

条件抽屉展示：

- 当前对话条件。
- 当前买家意向 hard 条件。
- preference 条件。
- unknown / 信息缺口。
- 本次对话覆盖了哪些条件。

条件抽屉不常驻占用左栏。

## 10. 推荐卡片

### 10.1 折叠态内容

每张推荐卡片折叠态展示：

- 排名。
- 名称。
- 推荐等级。
- 行业。
- 地区。
- 利润。
- PE / 估值。
- 推荐状态。
- 匹配摘要。
- 缺口摘要。
- 历史接触提示。
- 加入推荐列表按钮。

### 10.2 唯一主操作

未加入：

```text
[ 加入推荐列表 ]
```

已加入：

```text
[✓ 已加入推荐列表]  取消
```

折叠态不展示：

- 标记已推荐。
- 买家不感兴趣。
- 录入反馈。
- 查看详情。
- 更多菜单。

这些动作后置到推荐报告、统一业务更新或关系/跟进中。

### 10.3 历史接触提示

为买家找标的：

```text
接触：无锡某上市公司初步沟通中
```

为标的找买家：

```text
近30天已推荐：苏州器械、杭州医药商业；其中1个在谈
```

没有历史接触时不展示该行。

## 11. Debug Mode UI

### 11.1 显示规则

- 只有管理员能看到 Debug Mode 开关。
- 开启后才显示 Trace、prompt、raw output、parsed JSON 等信息。
- Debug Mode 不改变业务写入逻辑。
- 一期不设计 Dry Run。

### 11.2 展示位置

建议位置：

- 业务更新复核页右侧抽屉。
- 推荐对话系统回复下方的“查看 Trace”。
- 推荐结果卡片或候选池区域的“查看召回细节”。
- 后台任务状态详情。

### 11.3 内容清单

Debug 面板至少预留：

```text
job_id
node_name
provider
model
prompt_version
input_json
raw_output_text
parsed_output_json
schema_validation_error
retrieval_detail
prompt_tokens
completion_tokens
latency_ms
cost
error_message
```

### 12.1 目录结构

不能伪造真实推荐、真实报告或真实 AI 解析结果。

## 13. 验收清单

### 13.1 必须符合

- 工作台主体是“待我处理”，不是数据大屏。
- 买家管理默认核心是买家意向。
- 标的列表财务字段分列展示。
- 标的详情没有单独“推荐记录”tab。
- 推荐记录进入“关系/跟进”。
- 更新记录放最后一个 tab。
- 统一业务更新是“自动应用后复核”，不是“确认后应用”。
- 推荐页是两栏 + 条件抽屉。
- 推荐卡片折叠态只有“加入推荐列表”一个主操作。
- Debug Mode 只对管理员可见。
- 一期不出现 Dry Run 作为核心入口。
- 前端代码位于 `frontend/`。

### 13.2 不应出现

- 首页以大面积统计图表为主体。
- 推荐卡片放 4-5 个行内按钮。
- 条件快照常驻占据一整列。
- 把推荐记录和关系/跟进割裂成两个主要 tab。
- 把业务更新做成“必须等待 AI 完成后用户确认才能入库”的阻塞流程。
- 在后端未完成时伪造 LLM 真实结果。
